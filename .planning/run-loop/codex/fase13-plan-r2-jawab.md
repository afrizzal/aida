2. **HIGH — Urutan lock baru dapat menyebabkan deadlock.** [13-06 Task 3, baris 138](.planning/phases/13-integrations/13-06-PLAN.md:138) mengambil lock token sebelum mutasi. PATCH yang menugaskan tiket kepada pembuat token kemudian mengambil lock membership; demosi bersamaan menulis membership dahulu lalu, menurut [Task 2, baris 114](.planning/phases/13-integrations/13-06-PLAN.md:114), menunggu token. Kedua transaksi dapat saling menunggu. Sepakati urutan lock global dan uji race penugasan kepada pembuat token dengan barrier yang memaksa interleaving tersebut. **Terverifikasi di kode**: assignment memang mengambil `FOR SHARE` pada membership ([mutations.ts:232](src/lib/tickets/mutations.ts:232)); deadlock pada implementasi baru **belum terverifikasi**. Temuan nomor 5 belum tertutup dengan aman.

Perlu mekanisme menunda atau merekonsiliasi event dan tes yang menahan proses tepat sebelum link disimpan. **Belum terverifikasi** di implementasi.
