1. **HIGH — K127 masih menyediakan oracle HTTP, dan pesannya dapat salah.** **Terverifikasi di kode.** [errors.ts](src/lib/connection-test/errors.ts:215) menganggap setiap HTTP 401/403 sebagai `authentication_failed`, tanpa membuktikan bahwa respons berasal dari protokol yang diuji atau bahwa kredensial ditolak. Admin yang memilih URL Ollama dapat membedakan layanan HTTP yang menjawab 401/403 dari port tertutup; UI lalu menyatakan kredensial ditolak. [Test](tests/unit/connection-test-probes.test.ts:289) justru mengunci perilaku ini. Selain itu, [probe LLM](src/lib/llm/test-connection.ts:42) dan [embedding](src/lib/rag/embed-test-connection.ts:36) tidak memeriksa bentuk hasil; penerimaan sembarang 200 JSON sudah Anda verifikasi dan memberi sinyal layanan HTTP lain. [SECURITY.md](docs/SECURITY.md:32) terlalu yakin bahwa hasil auth membuktikan layanan protokol tersebut. **Perbaikan:** validasi bentuk respons sukses; perlakukan 401/403 dari URL Ollama sebagai `connection_failed` kecuali identitas protokol dan penolakan kredensial dapat dibuktikan. Tambahkan fake-server test untuk 200 JSON asing, 401/403 asing, dan port tertutup. Validasi bentuk saja tidak menghilangkan oracle layanan yang memang meniru Ollama atau kanal timing.

2. **HIGH — K130 membatasi respons, tetapi tidak membatasi antrean kerja pool.** **Terverifikasi di kode dan dokumentasi run.** [db.ts](src/lib/db.ts:5) membuat pool tanpa `connectionTimeoutMillis`; [limiter](src/lib/rate-limit/check-rate-limit.ts:124) tetap memulai transaksi sebelum memutuskan kuota. Dokumentasi perbaikan menyatakan permintaan pool yang melewati `maxWait` tetap antre dan kemudian menjalankan BEGIN/ROLLBACK. Saat pool jenuh, banjir request anonim dapat terus menambah pekerjaan yang bersaing dengan seluruh aplikasi, termasuk sesudah respons 429. **Belum terverifikasi:** laju banjir yang cukup untuk mengunci semua pengguna pada deployment nyata. Test [pool](tests/integration/rate-limit-atomic.test.ts:166) hanya menguji satu waiter dan pemulihan, bukan pertumbuhan antrean. **Perbaikan:** batasi admission sebelum `pool.connect`, batalkan atau beri batas waktu nyata pada waiter pool, dan uji banjir, panjang antrean, serta pemulihan query pengguna lain. Galat transaksi selain dua bentuk yang dikenali [masih dilempar](src/lib/rate-limit/check-rate-limit.ts:154), sehingga 429 untuk semua kondisi overload belum terbukti.

3. **HIGH — verifier gerbang dapat menerima `passed` image tanpa bukti image yang diperiksa.** **Terverifikasi di kode.** [imageRow](scripts/part-a-gate-check.ts:913) mempercayai log verifier terpisah, lalu mencocokkan hanya status, exit, target, tag, dan run ID pada log image. Jika log image berubah sesudah verifier berjalan—misalnya field `user`, `env`, image ID, atau seluruh baris teardown hilang—gerbang tetap dapat menghasilkan `passed`; [verifier image sendiri](scripts/test-image-check.ts:645) akan menolaknya bila dijalankan ulang. Test [F4](tests/unit/part-a-gate-check.test.ts:368) mengubah status dan identitas, tetapi tidak isi bukti yang diverifikasi. **Perbaikan:** jalankan fungsi validasi yang sama atas log dan exit aktual saat derivasi/check, atau ikat hasil verifier ke hash seluruh log dan periksa hash itu. Tambahkan mutasi tiap field dan teardown.

4. **HIGH — status `foreign resources unchanged` melebihi bukti.** **Terverifikasi di kode.** [Verifier](scripts/part-a-gate-check.ts:1095) memberi `passed` pada dua berkas identik, termasuk dua berkas kosong. [Perintah bukti](.planning/phases/08-security-hardening/08-24-PLAN.md:488) hanya mencakup container tertentu dan volume proyek `aida`; ia tidak membuktikan keadaan resource proyek lain, isi volume, atau keberhasilan setiap listing. **Perbaikan:** catat dan validasi exit setiap listing, persempit nama klaim ke cakupan yang benar-benar diukur, dan jangan menyimpulkan semua resource asing tidak tersentuh dari perbandingan ini. Ini bukan bukti bahwa skrip benar-benar menyentuh resource asing.

5. **MEDIUM — batas 10 berkas diterapkan sesudah parsing dan mengabaikan berkas kosong.** **Terverifikasi di kode.** [Reader](src/lib/http/read-bounded-form-data.ts:27) menyalin dan mem-parse seluruh body hingga 31 MiB sebelum validasi; [intake](src/app/api/public/intake/route.ts:60) membuang file kosong dan hanya menghitung field bernama `file`. Banyak part kecil, termasuk field asing, tetap diproses tanpa batas jumlah part. Ini melanggar batas “10 berkas per request” secara literal dan membuka amplifikasi CPU/memori; **belum terverifikasi** apakah satu request mencapai OOM pada batas container 512 MiB. **Perbaikan:** parser streaming dengan batas jumlah seluruh part, header, field, dan file sebelum alokasi; hitung juga file kosong. Uji multipart dengan banyak part kecil dan field asing.

6. **LOW — header keamanan tidak mencakup respons yang dibuat Caddy.** **Terverifikasi di konfigurasi; perilaku HTTP nyata belum diverifikasi.** [Caddyfile](Caddyfile:18) sendiri menjawab 404 untuk health probe dan menetapkan batas body, sedangkan header keamanan hanya dipasang [proxy Next](src/proxy.ts:61). Klaim header di semua jalur respons karenanya belum didukung. **Perbaikan:** pasang header statis yang relevan pada respons Caddy dan verifikasi 404/413 melalui Caddy sungguhan pada Bagian B.
