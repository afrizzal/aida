1. **HIGH — Flush saat tab tersembunyi merusak aturan satu simpan per view.** **Belum terverifikasi di kode:** [15-12 Task 1, baris 312](.planning/phases/15-work-views/15-12-PLAN.md:312) mengirim Y di samping X ketika tab menjadi tersembunyi, padahal view masih terpasang. Jika pengguna kembali saat keduanya berjalan lalu memilih Z, spesifikasi hanya memiliki satu `inFlight`; tidak jelas request mana yang ditunggu atau hasil mana yang menjadi `baseline`. X juga dapat commit setelah Y, meski pengguna hanya berpindah tab dan tidak meninggalkan halaman. Batas urutan yang ditulis untuk *document leave* tidak secara jelas mencakup kasus ini. Tentukan pelacakan semua request dan perilaku setelah halaman terlihat lagi; uji X tertahan, Y dikirim saat hidden, kembali dan pilih Z, lalu selesaikan request dalam urutan berbeda.

2. **HIGH — Syarat “wajib terkirim” belum dijamin oleh `keepalive`.** **Belum terverifikasi di kode:** [15-12 Task 1, baris 320–321](.planning/phases/15-work-views/15-12-PLAN.md:320) membatasi satu body ke 8.192 byte, tetapi itu tidak mencadangkan kuota browser: batas keepalive sekitar 64 KiB berlaku pada request yang masih berjalan secara bersama. Fetch berikutnya dapat ditolak; setelah dokumen hilang penolakan itu tidak dapat ditampilkan. `keepalive` juga bukan jaminan penerimaan atau commit server. Plan perlu membedakan **percobaan pengiriman**, penerimaan, dan penyimpanan; uji penolakan kuota serta tentukan pemulihan yang dapat ditawarkan, atau minta owner menerima batas tersebut bila “wajib terkirim” dimaksudkan sebagai jaminan mutlak.

3. **MEDIUM — Tes document leave tidak membuktikan urutan terhadap simpan yang masih diproses server.** **Belum terverifikasi di kode:** [15-12 Task 1, baris 345](.planning/phases/15-work-views/15-12-PLAN.md:345) menahan respons *setelah* `route.fetch()` selesai; X sudah mencapai server dan selesai sebelum Y dikirim. Tes itu dapat membuktikan pengiriman Y, tetapi tidak membuktikan hasil saat X masih memproses dan commit terakhir. [15-08 Task 3, baris 378](.planning/phases/15-work-views/15-08-PLAN.md:378) memang merencanakan uji urutan commit pada service secara terpisah. Tambahkan pengujian gabungan atau nyatakan batas bukti tes browser tersebut.

4. **MEDIUM — CX3-1 disederhanakan, bukan ditutup dalam arti hasil awal review.** **Belum terverifikasi di kode:** [15-12 keputusan 21 dan 23](.planning/phases/15-work-views/15-12-PLAN.md:259) mengisolasi listener dan membawa identitas sehingga simpan A tidak boleh menulis sebagai B. Namun A yang kembali sebelum simpan lamanya commit masih dapat melihat dasar basi dan kehilangan pilihan karena commit terakhir menang: itulah risiko CX3-1 semula, kini dinyatakan sebagai batas opsi c. Tes [Task 1, baris 346](.planning/phases/15-work-views/15-12-PLAN.md:346) kembali ke A setelah request lama selesai, sehingga tidak menguji urutan itu. Status yang tepat: isolasi antaridentitas direncanakan; risiko pilihan A tertimpa diterima sebagai batas, bukan terbukti hilang.
