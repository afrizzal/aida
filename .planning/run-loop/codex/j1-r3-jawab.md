1. **KRITIS — teardown dapat menghapus resource yang justru menyebabkan preflight berhenti.** **Terverifikasi di kode:** [egress setup](tests/integration/egress-isolation.test.ts:153) mengambil lock sebelum memeriksa project, nama, dan tag. Jika pemeriksaan itu gagal, `afterAll` tetap menjalankan cleanup karena `releaseLock` sudah terisi. Contohnya, tag egress yang sudah ada dengan label run yang sama membuat `assertTagsFree` menolak build, tetapi kemudian dapat dihapus oleh teardown. Begitu pula container project yang sudah ada dengan label run yang sama. Ini melanggar tujuan “berhenti tanpa menyentuhnya”; K114 dan K115 belum tertutup. Cleanup harus dibatasi pada resource yang dapat dibuktikan dibuat invokasi ini, termasuk ketika build atau `up` gagal sebagian; preflight yang gagal sebelum ada pembuatan tidak boleh memicu cleanup Docker.

2. **TINGGI — scope egress masih mencakup project lain.** **Terverifikasi di kode:** [pembersih](scripts/test-docker-cleanup.ts:135) memakai `startsWith("aida-test-egress")`, sehingga misalnya `aida-test-egress-other_...` dengan label run yang sama juga cocok. Lock dan label run tidak membuktikan kepemilikan suite. Gunakan identitas project dan nama/ID resource yang tepat, bukan hanya awalan bersama. [Test scope](tests/unit/test-docker-cleanup.test.ts:188) hanya membandingkan dengan `aida-test-integration`; ia bisa lolos meskipun bug ini ada. Test juga belum menjalankan hook `afterAll` ketika lock atau preflight gagal.

3. **TINGGI — K117 masih dapat melaporkan sisa sebagai sudah hilang.** **Terverifikasi di kode:** [applyCleanup](scripts/test-docker-cleanup.ts:193) menganggap *setiap* pesan yang mengandung `no such` berarti resource hilang. Kegagalan koneksi socket seperti `no such file or directory` juga cocok, sehingga resource yang masih ada dapat masuk `gone` dan hasil dianggap sukses. Di [assertNamesAbsent](tests/support/docker-test-preflight.ts:218), `no such|not found` sama luasnya dan dapat menyalahartikan galat daemon sebagai nama kosong. Cocokkan galat ketidakadaan khusus jenis dan referensi resource; galat lain harus gagal. **Belum terverifikasi:** pesan tepat yang akan dihasilkan daemon ini pada tiap kegagalan.

4. **SEDANG — K116 dan K118 belum lengkap sebagai bukti.** **Terverifikasi di kode:** setelah `up`, [ledger egress](tests/integration/egress-isolation.test.ts:184) mencatat network dan volume hanya sebagai `planned`; hasil `compose ps` tidak diperiksa kode keluarnya. Probe ruang dan container negative-control juga tidak tercatat sebagai `created`. Jadi klaim ledger lengkap belum terpenuhi. `run --pull never` ada, tetapi `--no-build` yang disebut dalam keputusan tidak tampak; negative-control saat ini memakai image tanpa `build`. **Belum terverifikasi:** resource aktual, image dasar yang ditarik, dan perilaku suite egress sampai 0a2 dijalankan.

   Untuk K118, **terverifikasi di kode** bahwa `DockerRootDir` di-bind read-only dan dua hasil `df` diambil nilai terkecilnya. **Belum terverifikasi** bahwa filesystem itu mencakup seluruh penyimpanan builder pada daemon ini, atau disk VM host memang berada pada filesystem home. Batas host tertulis di rencana, tetapi belum tampak dalam bagian menunggu owner di `LAPORAN.md`; sertakan di sana. K119 untuk parsing `df` dan pemilihan nilai terkecil tertutup oleh test kode, sementara bukti pewarisan run ID saya terima sebagai hasil orkestrator, bukan verifikasi mandiri.
