<interfaces>
<!-- The self-host reality these scripts and docs must match exactly. -->

**Compose services:** `db` (pgvector/pgvector:pg16, **publishes no host port** — internal network only), `migrate` (one-shot `pnpm prisma migrate deploy`, `restart: "no"`, gated on `db` healthy), `app` (`node server.js`), `worker` (`node dist/worker.mjs`), `caddy` (ports 80/443).

**Named volumes:** `postgres_data`, `uploads_data` (mounted ONLY by `app` at `/data/uploads`), `caddy_data`, `caddy_config`.

**Because `db` has no published host port, every DB operation must go through `docker compose exec db …`.** Host-side `psql`/`pg_dump` cannot reach it.

**The `app`/`worker` image is `node:22-alpine`** with `CMD ["node","server.js"]` and NO `ENTRYPOINT`. That means `docker compose run --rm -T --no-deps --entrypoint sh app -c '<busybox shell command>'` gives you a throwaway container with `uploads_data` already mounted at `/data/uploads` and busybox `tar` available — no need to guess the compose-prefixed volume name.

**Postgres credentials** come from `.env`: `POSTGRES_USER` (default `aida`), `POSTGRES_PASSWORD`, `POSTGRES_DB` (default `aida`).

**`AuditEvent` carries a Postgres trigger** (`aida_audit_event_no_update_delete`) that raises on UPDATE and DELETE. `pg_restore --clean --if-exists` issues `DROP TABLE`, not `DELETE`, so restore is unaffected — but the docs must warn operators never to try to prune audit rows with `DELETE`.

**pgvector:** the dump contains `CREATE EXTENSION vector`; the restore target MUST be a `pgvector/pgvector:pg16` image (a stock `postgres:16` will fail). Say so in the docs.

**Healthcheck contract** (`src/app/api/health/route.ts`): `GET /api/health` returns `{ status: "ok", db: "connected", worker: { lastRunAt } }` on success and HTTP 503 `{ status: "error", db: "unreachable" }` when Postgres is unreachable. `worker.lastRunAt` is the `SystemSetting['heartbeat:lastRunAt']` ISO-8601 string written by the worker's heartbeat job — a stale value means the worker is down even though the app is up.

**`.gitattributes` from 07-01 pins `*.sh text eol=lf`** — do not fight it; CRLF would break the shebang inside the containers.

Deferred by D-08: no built-in scheduler/sidecar in v1. The docs show a cron example instead.
</interfaces>
