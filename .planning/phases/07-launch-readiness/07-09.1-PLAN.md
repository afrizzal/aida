<objective>

Purpose: those three items have been carried since Phase 4. Two of them guard AIDA's two most expensive public promises — "your ticket data stays on your server" and "no fabricated stats". <context>

<design_decisions>
These are locked. They differ from 07-09's Task 3 wording on purpose — record the reasoning in the SUMMARY.

**D-1. Egress is proven by denial, not observation.** Rather than watching traffic while flows run, run the whole stack on a Docker network with `internal: true` (no route to the internet) and assert every AI/email flow still succeeds. That proves no external dependency is *required*. Then add a capture sidecar so *attempted* destinations are also recorded — a telemetry call that fails silently is invisible to the success/failure signal alone, and it is exactly what this test exists to catch.

**D-2. Honesty invariants are proven with an ADVERSARIAL stub, not a real model.** 07-09's Task 3 asked a human to judge whether a real model's narrative contradicts the SQL numbers. That tests the *model*, is non-deterministic, and cannot run in CI. The correct test inverts it: make the stub return a narrative containing deliberately wrong numbers and a citation to an article that was never retrieved, then assert the product ignores both. This proves a property we actually control, and it is the property the docs claim.

`src/app/(app)/insights/sla-csat-card.tsx:23` already declares this invariant **LOCKED** ("never parsed from `narrative.summary`") and no test guards it. That is the target.

Ollama is NOT installed on the dev machine, and this design deliberately does not need it.

**D-3. "Dark mode legibility" becomes a contrast assertion.** Add `@axe-core/playwright` and assert zero contrast violations in both themes on the surfaces 07-08's screenshots did not cover. Aesthetic judgement is not automatable and is not a release gate — it gets re-logged as feedback, not as a blocking item.

**D-4. Do not weaken any assertion to make a test pass.** If a technique does not work in this environment (e.g. a capture sidecar under Docker Desktop on Windows), say so plainly, ship the strongest thing that does work, and record the residual honestly. A test that passes without proving its claim is worse than no test.
</design_decisions>
