**Toolchain pins:** `packageManager: "pnpm@10.34.4"`, `engines.node: ">=22"`, `volta.node: "22.23.1"`, `.nvmrc` contains `22`.

**Two build-time facts that will break CI if ignored:**
1. `prisma.config.ts` calls `env("DATABASE_URL")` at module load, so even `prisma generate` (which never connects) fails when the variable is absent. CI must `cp .env.example .env` before any prisma command.
2. `src/generated/prisma/client` is gitignored — `pnpm db:generate` MUST run before `typecheck` and `build`, or both fail on unresolved imports.

**Integration tests** use Testcontainers + `@testcontainers/postgresql` and require Node 22 (undici@8 constraint). They are slower and Docker-dependent, so they belong in their own scheduled workflow — a flaky required job would poison the README's CI badge on day one.

**docs/SECURITY.md already exists** and is the ENGINEERING security model (threat model, controls). `.github/SECURITY.md` is a DIFFERENT document: the GitHub-standard disclosure policy (D-11). Do not merge them; cross-link them.

**CLAUDE.md non-negotiables that CONTRIBUTING.md must restate for outside contributors:** model-agnostic LLM layer (`lib/llm/` only, never a hardcoded vendor), privacy-first (data stays on the operator's server, keys encrypted at rest), human-in-the-loop for AI sends (AI drafts, a human approves), honest claims (never "trained/fine-tuned"; relative metrics only), single-server stack discipline (**no Redis, no extra services — the queue is pg-boss on Postgres and the vector store is pgvector in the same Postgres**), and the design system contract in `.planning/DESIGN-SYSTEM.md`.

    ```yaml
    name: CI

    on:
      push:
        branches: [master]
      pull_request:
      workflow_dispatch:

    concurrency:
      group: ci-${{ github.ref }}
      cancel-in-progress: true

    jobs:
      build:
        name: lint · typecheck · test · build
        runs-on: ubuntu-latest
        timeout-minutes: 20
        steps:
          - uses: actions/checkout@v5

          - uses: pnpm/action-setup@v4          # reads the packageManager field in package.json

          - uses: actions/setup-node@v5
            with:
              node-version-file: .nvmrc
              cache: pnpm

          - run: pnpm install --frozen-lockfile

          # prisma.config.ts evaluates env("DATABASE_URL") at module load — even `generate`
          # (which never connects) fails without it. .env.example holds only placeholders.
          - name: Provide placeholder env
            run: cp .env.example .env

          # src/generated/prisma/client is gitignored; typecheck and build both need it.
          - run: pnpm db:generate

          - run: pnpm lint
          - run: pnpm typecheck
          - run: pnpm test
          - run: pnpm build
    ```
    Pin action versions exactly as written above. If `pnpm/action-setup@v4` is unavailable in your environment's action index, keep `@v4` anyway — resolution happens on GitHub, not locally.

       ```bash
       git clone https://github.com/afrizzal/aida.git && cd aida
       pnpm install
       cp .env.example .env      # required: prisma.config.ts reads DATABASE_URL at load time
       ```

       - Import the Prisma client from `@/generated/prisma/client`, never `@prisma/client`.
       - All tenant data access goes through `scopedDb(orgId)` / `getScopedDb()`; `src/lib/auth.ts` is the one exception and uses bare `prisma`.
       - Raw SQL is never scoped automatically — any `$queryRaw` touching tenant tables must filter `organizationId` explicitly.
       - Files under `src/lib/worker/` (and anything they import) use RELATIVE imports only, because the worker is esbuild-bundled.
       - There is exactly one ticket write path (`createTicket`), one KB write path (`createKbArticle`), one Markdown/HTML sanitiser (`src/lib/markdown/render.ts`), one encryption primitive (`src/lib/crypto/secret-box.ts`) and one audit write path (`recordAuditEvent`). Do not add a second.
       - Every mutating Settings Server Action starts with `await requireOrgAdmin()`.
       - UI must follow `.planning/DESIGN-SYSTEM.md`: design tokens only (no hex/oklch in components), explicit `text-[Npx]` sizes.
    5. *Architectural non-negotiables* — restate CLAUDE.md's rules verbatim in spirit: the LLM layer stays model-agnostic (OpenAI/Anthropic/Ollama behind `lib/llm/`), AI must remain fully toggleable off, nothing is sent to any third party other than the operator-configured LLM, AI never sends to a customer without human approval, and **the stack stays single-server — no Redis, no extra queue or vector service; pg-boss and pgvector both live in the same Postgres.** A PR that adds a new runtime service will be declined.
    6. *Honest claims* — contributions to README/docs/marketing copy may not invent metrics, may not claim models are "trained" or "fine-tuned" (they are consumed via API / orchestrated), and comparisons stay relative.
    7. *Commit and PR style* — Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`, `test:`, `refactor:`), one logical change per PR, link the issue, fill in the PR template.
    8. *License* — contributions are licensed under Apache-2.0.

    ```markdown
    ## Supported Versions
    ## Reporting a Vulnerability
    ## What to include
    ## Our commitment
    ## Scope
    ## Out of scope
    ## Security model
    ```

    Content: v1.x is the supported line (pre-1.0 = only the latest release). Report privately via GitHub's **Report a vulnerability** (Security > Advisories) or the maintainer email — **never** a public issue. In scope: the AIDA application, the shipped Dockerfile/compose stack, the public intake/status endpoints, tenant isolation, and credential-at-rest handling. Out of scope: vulnerabilities in a user's own LLM provider or SMTP/IMAP host, issues requiring a pre-compromised server or a self-signed misconfiguration, and findings against a fork. The *Security model* section is 2-3 sentences linking to `../docs/SECURITY.md` for the engineering detail — do not restate it.
