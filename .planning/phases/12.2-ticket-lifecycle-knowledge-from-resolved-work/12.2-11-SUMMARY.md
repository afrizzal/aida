   - The edited title is saved ("Draft saved. It is not published."). Before the publish, /kb and the database have no article with that title, and `publishedArticleId` is null.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Cross-file cleanup needs to delete this file's own proposal audit rows**
- **Found during:** Task 1 (design of afterAll).
- **Issue:** kb-proposals.spec.ts sorts before phase5-rag.spec.ts, whose first test asserts the KB empty state at zero articles. The article published through the UI cannot be removed normally. Its proposal restricts the article's delete; the proposal's KB_PROPOSAL_GENERATED AuditEvent restricts the proposal's delete; and AuditEvent refuses DELETE through its append-only trigger.
- **Fix:**
  - `cleanUp()` deletes only the AuditEvent rows that reference this file's proposals (`organizationId` and `kbProposalId` terms). It does so inside one transaction under `SET LOCAL session_replication_role = replica`. The e2e user is the Testcontainers superuser, and the database is thrown away after the run.
  - The role is set back to `origin` before the sources, proposals and articles are deleted, so their foreign keys stay enforced.
  - The cleanup then asserts that no proposal of this run and none of its articles is left.
  - The product rule is unchanged. The trigger stays in force for every other session.
- **Proof:** run 11 (49 passed, phase5-rag's empty state included).
- **Files modified:** tests/e2e/kb-proposals.spec.ts
- **Commit:** 175050a

**2. [Rule 1 - Bug] Light `--destructive` failed contrast as text on its own `/10` tint**
- **Found during:** Task 3 (run 9).
- **Issue:** The Failed chip measured 3.93:1 on `/kb/proposals` in light mode. The same classes are used by the "Embedding failed" chip, the destructive Button variant ("Reject proposal") and every error callout, but no scan had covered them in that state.
- **Fix:** `--destructive` (light) changed from `oklch(0.577 0.245 27.325)` to `oklch(0.48 0.245 27.325)`, following DESIGN-SYSTEM's token-level rule (lightness only, same hue and chroma). Computed with sRGB clipping, which reproduces axe's old 3.93:1, the new value gives about:
  - 5.16:1 on background;
  - 5.25:1 on card;
  - 4.80:1 on muted;
  - 4.54:1 on accent;
  - 6.32:1 for white text on solid destructive.

  Dark mode is unchanged (it already passed). The change is recorded as item 5 of the DESIGN-SYSTEM contrast fix note. The darker red is a human visual-pass item.
- **Conflict with the plan:** Task 2's acceptance check `git diff --name-only … -- src` was meant to catch a production test hook, and it now lists this file. The plan's rule "a contrast violation is reported as found; never relax the rule set" is kept: the violation is reported here, the rule set is untouched, and the value is fixed rather than exempted.
- **Files modified:** src/app/globals.css, .planning/DESIGN-SYSTEM.md
- **Commit:** 66867bd

**3. [Rule 1 - Test bug] AI triage of seeded tickets shared the stub's chat route**
- **Found during:** Task 1 (run 1).
- **Fix:** `createTicketWithoutTriage` creates every seeded ticket with AI off, so no triage job is enqueued, and then restores the previous switch. The proposal-request assertions also filter on `PROPOSAL_SYSTEM_PROMPT`.

**4. [Rule 1 - Test timing] Editor fills raced react-hook-form's mount**

- **Commit:** f09f2c3
