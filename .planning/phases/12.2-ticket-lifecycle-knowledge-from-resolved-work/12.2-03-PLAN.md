<objective>
Give every LLM adapter a bounded call and give the generation job a way to tell configuration errors and invalid output (terminal FAILED) from transient failures (bounded retry) without reading raw error text (D-14, pattern findings C4 and C5); and make the shared kb-embed-article job safe when two jobs run for one article, a job holds old text (review R2-1), a job's vectors come from a model that is no longer configured (review P6) or a job fails after another job completed the article (review R3-1), before plan 12.2-05's "Retry indexing" for a PENDING article makes a second job reachable from one click (D-06).

Purpose: D-14 requires terminal failures for configuration and invalid output and retries only for transient failures; Ollama today can hang forever. This plan is the phase's plan for changes to shared AI infrastructure that existing features use (the Ollama adapter serves triage, drafts and Insight; the embed job serves the manual KB path and re-embed-all), and it runs in wave 1, so the job is fixed before any 12.2 path depends on it.
Output: `src/lib/llm/errors.ts`, the Ollama timeout, typed throw sites, two unit tests; the locked chunk swap with text and model freshness checks and the one guarded FAILED writer in `src/lib/worker/jobs/kb-embed-article.ts`, with one integration race test.
</objective>
