# Phase 12.2 — UI Design Contract

> Visual and interaction contract for AIDA-18 (KB article proposals from resolved tickets). Generated by gsd-ui-researcher under the run charter (unattended, no user questions); every choice not fixed upstream is marked **[RL]** and listed under "Assumptions". To be verified by gsd-ui-checker.
>
> **Binding parent:** `.planning/DESIGN-SYSTEM.md`. Conventions carried from `12.1-UI-SPEC.md`: spacing 4/8/16/24/32, 16px callout padding, `text-[13px]` overrides on shadcn internals, 15px dialog titles, inline `role="alert"` errors in dialogs, toasts for success, "refusal returned → Nothing was changed; call rejected → result not known" (P11 D2), disabled-with-reason menu items, `LocalDateTime` for visible times, warning notices with `text-foreground` text and a `text-warning` icon (12.1 contrast finding 1).
>
> **Scope (closed list):** (1) the entry point that starts a proposal from 1 to 5 selected tickets (inbox bulk bar and ticket "More ticket actions" menu); (2) the proposal list at `/kb/proposals` with its statuses; (3) the review page `/kb/proposals/[id]` (editor, sources, notices, save, reject, approve and publish); (4) a link from the KB page to the proposal list for admins. Nothing else changes. The KB list, article pages, RAG, Insight and search never show a proposal [CTX D-05].

Source legend: **[CTX D-nn]** = `12.2-CONTEXT.md`; **[REQ]** = AIDA-18; **[DS §n]** = `DESIGN-SYSTEM.md`; **[code]** = existing code at `16bafee`; **[P12.1]** = convention from `12.1-UI-SPEC.md`; **[RL]** = Claude's discretion, decided conservatively.

**Terminology [RL]:** user-facing copy says **"proposal"** for a `KbProposal` and **"article"** for a published `KbArticle`. Ticket states keep the 12.1 wording "status"; the proposal's own `status` is shown as a chip label (Generating, Draft, Rejected, Published, Failed).

## Surface 1 — Start a proposal (D-01, D-07, D-09)

### 1a. Entry points [RL, Assumption 1]
- **Inbox bulk bar:** a new outline `Button size="sm" className="text-[13px]"` with `Sparkles size-4` and "Propose KB article…", placed after the existing pickers. **Admins only** (non-admins never see it; the server refuses anyway). Visible for any selection; disabled via `aria-disabled="true"` (focusable, with `aria-describedby` to a 12px muted reason under the bar) when: AI is off ("Entry unavailable: AI off"), more than 5 selected ("Entry unavailable: too many"), or the bar's call lock/unknown-outcome lock is on (existing reason). Eligibility of each ticket is not judged client-side; the dialog shows it.
- **Ticket top bar:** `TicketActionsMenu` gains, after "Merge into another ticket…", a `DropdownMenuItem` with `Sparkles` and "Propose KB article…", admins only. Disabled with a second 12px muted reason line (also its `aria-describedby`) when AI is off, the ticket's group is not RESOLVED or CLOSED ("Entry unavailable: not resolved"), or it is a merged source ("Entry unavailable: merged"). Opens the Start dialog with this one ticket.

### 1b. Start dialog
`DialogContent sm:max-w-[520px]`, body `space-y-4`:
- Title "Start title"; description (13px muted) "Start description".
- Ticket list `<ul className="divide-y divide-border/70 rounded-lg border border-border/70">`, one `<li className="flex flex-wrap items-center gap-2 px-4 py-2 text-[13px]">` per ticket: `#{number}` (`tabular-nums text-muted-foreground`), subject (`min-w-0 max-w-[240px] truncate`, full subject in `title`), `StateChip`.
- Privacy notice (warning style, `TriangleAlert`): "Customer content notice" [CTX 12.2-o1].
- Info line (12px muted, `Info size-4`): "Start inputs line" [CTX D-10].
- Callout slot above the footer (`role="alert"`).
- Footer: "Close without starting" (outline, Copywriting "Start dismiss"), "Generate proposal" (default). Pending: `Loader2 mr-2 size-4 animate-spin` + "Starting…", all controls disabled, `Esc` and outside click do not close [P12.1].
- **Success:** the request returns the proposal id; the dialog closes, `toast.success` "Started toast", and the browser navigates to `/kb/proposals/{id}` (which shows Generating). The bulk selection is kept [RL].
- **Refusal with per-ticket reasons** (D-07: the whole request refused, never a silent drop): callout "Nothing was changed. Selection refused intro" and, under each failing `<li>`, a 12px destructive reason line from the "Ticket refusal: …" rows (merged source names its target as a link `#{targetNumber}`). The submit stays disabled; focus moves to the callout heading (`tabIndex={-1}`) [RL]. To fix, the admin closes the dialog and changes the selection.
- **Other refusals:** one callout row ("Start error: …"); submit disabled for AI off, not allowed, membership ended; re-enabled for unknown; focus per the focus table.
- **Rejected call:** "Start outcome unknown"; submit disabled; focus on "Close without starting".

## Surface 2 — Proposal list `/kb/proposals` (D-01, D-03, D-15)

- Server page. Membership checked first; a non-admin or ended membership gets the matching EmptyState ("Not allowed heading/body" with `BookOpen`, or "Membership ended") and **no data is loaded** [CTX D-01].
- `/kb` (existing page) gains, for admins only, an outline `Button size="sm"` "Proposals" with the count of DRAFT proposals in `tabular-nums` when above 0, left of "New article" [RL]. Non-admins see no link.
- Layout: header `flex items-center justify-between px-6 py-4`: `<h1>` "Proposals page title", a 13px muted description "Proposals page description" below it; right side outline "Back to articles" link. AI-off notice (warning style, under the header, `mx-6`) when AI is off: "List AI off notice".
- Rows (`divide-y divide-border`, newest first, every status shown, no filter [RL]): `<Link className="flex flex-wrap items-center gap-2 px-6 py-3 hover:bg-muted/50">` with `KbProposalStatusChip`, title (`min-w-0 flex-1 truncate text-[13px] font-semibold`; "Untitled while generating" when null), 12px muted "Source count", 12px muted relative time (`LocalDateTime` title). A FAILED row also shows its 12px muted short reason ("Failure short: …").
- Empty: EmptyState `Sparkles`, "List empty heading" / "List empty body".
- Loading: server-rendered, no skeleton. While any row is GENERATING the page refreshes every 5 s via `router.refresh()` until none is [RL, Assumption 3]; a polite live region announces "Generation finished announcement" when a row leaves GENERATING.

## Surface 3 — Review page `/kb/proposals/[id]` (D-06, D-08, D-10, D-11, D-15, D-16)

### 3a. Access and not found
Membership then admin check, server-side, for the page and every action. A missing id or another organization's id renders EmptyState `BookOpen` "Not found heading/body" (never a distinct "other workspace" message) [CTX D-01].

### 3b. Layout
`flex flex-col gap-6 px-6 py-6`:
1. Header `flex flex-wrap items-center gap-2`: `<h1>` "Review page title", `KbProposalStatusChip`, 12px muted "Requested by line".
2. **AI notice** (accent block, always shown in DRAFT): "AI notice".
3. **Customer content warning** (warning block, DRAFT): "Customer content notice".
4. Conditional warnings (warning block each, `role="status"`): "Source changed notice" when any source changed after generation (D-08), listing the changed `#{number}`s; "Truncation notice" when input was truncated (D-10).
5. Grid `grid gap-6 lg:grid-cols-[minmax(0,1fr)_320px]`: left = editor (3c); right = Sources card (3d).
6. Action bar (3e), `sticky bottom-0 border-t border-border/70 bg-background/80 backdrop-blur-sm px-6 py-4` [RL].

### 3c. Editor (DRAFT only)
Form `space-y-4`, mirrors `KbArticleForm` [code]: Title `Input` (3 to 120 chars, as KB), help "Title help"; Body `Textarea min-h-[360px] font-mono text-[13px]` labelled "Body label", help "Body help". Source-reference markers (`[T1]`-style) in the body are refused, fail-closed: Save and Publish return a field refusal on Body with Copywriting "Citation marker error" and nothing is changed or silently stripped (D-11); focus moves to the Body field (the "Field error" row in 3i). A "Preview" toggle (outline `size="sm"`, `aria-pressed`) swaps the textarea for the body rendered through `renderMarkdown` in a `prose`-free `text-[13px]` container [RL]. Unsaved changes: the "Approve and publish…" button is disabled with reason "Publish unavailable: unsaved" so what is published is always the saved version [RL, Assumption 5].

### 3d. Sources card
`Card border-border/70 shadow-sm p-4 space-y-2`, heading 15px "Sources heading". One row per source: `Ticket size-4` + link `#{number} {subject}` to `/tickets/{id}` (`text-primary-emphasis hover:underline`, `ExternalLink size-3` not used: same tab [RL]), `StateChip`, and, when changed since generation, a 12px line with `TriangleAlert text-warning` "Source changed short". Citations: under each source, 12px muted "Cited in: {markers}" when the model cited it; a source never cited shows "Not cited". Footer 12px muted "Sources internal note". A source deleted or moved out of the organization shows "Source unavailable" instead of a link.

### 3e. Action bar by status
- **DRAFT:** "Save draft" (default only when the form is dirty, else outline and disabled), "Reject…" (outline, `X`), "Approve and publish…" (default). Pending save: "Saving…", fields locked. Save success: `toast.success` "Saved toast", version refreshes, never publishes [CTX D-15].
- **GENERATING:** no editor; body area shows `Skeleton` lines with `aria-busy="true"` and the text "Generating body"; the page refreshes every 5 s (as Surface 2). After 10 minutes still GENERATING, a warning notice "Stuck notice" with outline "Restart generation" (re-enqueues the same id, D-13) [RL, Assumption 6].
- **FAILED:** destructive callout (no "Nothing was changed." prefix) "Failure: …" row by code; action "Start a new proposal" (outline) opens the Start dialog prefilled with the same tickets (regeneration creates a new proposal, D-16). Disabled with "Entry unavailable: AI off" when AI is off. Read-only, no editor.
- **REJECTED:** neutral notice "Rejected notice" with reviewer and `LocalDateTime`; read-only rendered title and body; "Start a new proposal" as above. Never a publish control [CTX D-16].
- **PUBLISHED:** success-style line "Published notice" with link "Open article" to `/kb/{publishedArticleId}` and `KbEmbeddingStatusChip`; if embedding FAILED, outline "Retry indexing" (re-enqueue, D-06) [RL]. Read-only.

### 3f. Approve and publish dialog (one explicit confirmation)
`DialogContent sm:max-w-[520px]`: title "Publish title"; description "Publish description"; checklist `<ul className="list-disc space-y-1 pl-4 text-[13px]">` "Publish checklist"; warning notice "Publish cannot be undone". One required native checkbox (via `@/components/ui/checkbox`) labelled "Publish confirm checkbox"; "Publish article" (default) stays disabled until it is checked [RL, Assumption 4]. Footer "Keep reviewing" (outline) first. Pending "Publishing…", `Esc`/outside click do not close. **Success:** dialog closes, `toast.success` "Published toast", page refreshes to PUBLISHED. **Refusal:** callout "Nothing was changed." + "Publish error: …"; "Publish article" disabled; focus "Keep reviewing". **Conflict** (version or status changed): callout "Conflict" row, plus outline "Reload proposal" in the callout. **Rejected call:** "Publish outcome unknown", publish disabled, focus "Keep reviewing" [P11 D2] — a second publish is safe server-side (D-16) but the UI never retries on its own.

### 3g. Reject dialog
Title "Reject title"; description "Reject description"; footer "Keep proposal" (outline, initial focus) and "Reject proposal" (destructive). Pending "Rejecting…". Success: closes, `toast.success` "Rejected toast", page refreshes to REJECTED. Refusal / conflict / rejected call: as 3f with "Reject error: …" and "Reject outcome unknown".

### 3h. Save conflict
A save refused for version or status change shows the "Conflict" callout above the action bar with "Reload proposal"; the local edits stay in the fields (not discarded) so the admin can copy them; Save is disabled until reload [RL].

### 3i. Focus after every outcome

| Event | Focus goes to |
|---|---|
| Start dialog opens | "Generate proposal" when every ticket is listed; the dialog never opens on an empty selection |
| Start dialog closed without starting | The trigger (bulk button, or "More ticket actions" trigger via explicit `onCloseAutoFocus`, as 12 UI-WR-03) |
| Start success | The review page `<h1>` (`tabIndex={-1}`) after navigation |
| Start selection refusal | The callout heading (`tabIndex={-1}`) |
| Start other refusal / rejected call | "Close without starting" when submit stays disabled; else the submit button |
| Review page load | Normal document order; no autofocus |
| Save success | "Save draft" button (now disabled → focus the `<h1>`) [RL: never on a disabled control] |
| Save refusal / conflict / rejected call | The callout (`tabIndex={-1}`, `role="alert"`) |
| Field error | The first invalid field |
| Publish / Reject dialog opens | The confirm checkbox / "Keep proposal" |
| Publish / Reject dialog closed without acting | The button that opened it |
| Publish / Reject success | The page `<h1>` after refresh |
| Publish / Reject refusal, conflict, rejected call | "Keep reviewing" / "Keep proposal" |
| "Reload proposal" | The page `<h1>` after reload |
| Generation finished (polling) | Focus is not moved; the live region announces it |
| Restart / Retry indexing outcome (success, refusal, rejected call) | The pressed button; success in a `role="status"` line under it, refusal ("Restart / Retry error") or rejected call ("Restart outcome unknown" / "Retry indexing outcome unknown") in a `role="alert"` line; after a rejected call the button stays disabled until reload |

## Assumptions [RL]

1. **Entry points:** both the inbox bulk bar (1 to 5 selected) and the ticket "More ticket actions" menu (one ticket); admins only; disabled with a reason, never hidden for admins.
2. **Routes:** `/kb/proposals` and `/kb/proposals/[id]`, reached from a "Proposals" button on `/kb`; no new sidebar item (sidebar unchanged).
3. **Status updates by polling** (`router.refresh()` every 5 s while GENERATING), no websocket or new mechanism.
4. **Publish confirmation** = dialog + one required checkbox; primary (not destructive) button; reject = destructive.
5. **Publish publishes only the saved version**; unsaved edits disable publish with a reason.
6. **Stuck threshold** 10 minutes, then a manual "Restart generation" (D-13 recovery); never automatic.
7. **Citation markers** are shown to the reviewer beside each source ("Cited in"), not rendered into the article (D-11); the exact marker format is the planner's.
8. AI off disables only starting new proposals; reviewing, editing, rejecting and publishing existing drafts stay available (D-09: a stored draft is reviewable) — publish still never calls the LLM.
