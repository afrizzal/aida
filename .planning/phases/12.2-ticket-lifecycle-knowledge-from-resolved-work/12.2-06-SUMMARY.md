# Phase 12.2 Plan 06: Proposal copy, status chip and outcome resolver Summary

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Correctness] The publish and reject callout prefix is composed in the mapping, not in the dialog**
- **Found during:** Task 2
- **Issue:** The plan says the dialog adds "Nothing was changed." before the unprefixed Publish error and Reject error rows. However, the Conflict row already carries the prefix, the membership-ended row must never get it, and the outcome-unknown rows must not get it either. A dialog that prefixed the message would need to branch on the code, which the resolver design (components only apply the view) rules out.
- **Fix:** The constants stay unprefixed and verbatim, as the plan requires. `publishRefusalCopy` and `rejectRefusalCopy` return the prefixed callout text, so the dialogs of plan 12.2-09 render `view.message` as is and must not add the prefix again. The test documents which rows carry the prefix themselves and which the mapping prefixes.
- **Files:** src/lib/kb/proposal-copy.ts, tests/unit/proposal-copy.test.ts
- **Commit:** 8ded6fb

**2. [Rule 2 - Correctness] MEMBERSHIP_ENDED on restart and retry indexing maps to "Membership ended"**
- **Found during:** Task 2
- **Issue:** The Task 3 behavior says restart and retry refusals give "Restart / Retry error" ("Nothing was changed. Wait a moment and try again."). Waiting cannot help an ended member, and the UI-SPEC rules treat the "Your access…" row as the returned refusal for an ended membership.
- **Fix:** MEMBERSHIP_ENDED maps to the "Membership ended" row. Every other maintenance code gives "Restart / Retry error", as planned. Save, publish and reject map MEMBERSHIP_ENDED the same way. No new copy was introduced.
- **Commit:** 8ded6fb

**3. [Rule 2 - Totality] Rows for codes with no row of their own**
- NOT_FOUND on save, publish and reject returns "Nothing was changed. It may have been removed. Go back to Proposals to see the current list." (the prefix plus the "Not found body" row).
- A MERGED ticket refusal without `mergedIntoNumber` falls back to "Entry unavailable: merged".
- A refusal code outside an action's contract list resolves to the outcome-unknown view.
- No new words were written for any of these.
- **Commits:** 8ded6fb, b31c629

**4. [Rule 2 - Completeness] Small additions for the UI plans**
- `REJECT_TRIGGER` = "Reject…" is the UI-SPEC 3e action-bar text, which is not a Copywriting row.
- `ticketRefusalMergedParts(n)` lets the dialog render `#{targetNumber}` as a link; the test checks that its parts equal the row.
- `PROPOSAL_ACTIONS` and `ProposalAction` are defined in proposal-copy.ts and re-exported as a type from proposal-outcome.ts, which avoids an import cycle.
- `isProposalField` and `isProposalFieldCode` were added.
- A type-level test checks that every service result type (request, save, publish, reject, restart, retry) is accepted as an `ActionOutcome` unchanged. Plan 12.2-08 depends on this.
- **Commits:** 8ded6fb, b31c629

**5. Disabled-submit choices the plan left open (documented, not invented copy)**
- A non-field save refusal keeps save disabled until reload, because only a reload can change these outcomes.
- A field save refusal keeps save enabled.
- Restart and retry refusals keep the pressed button enabled, because the row says "Wait a moment and try again".
- Successes never disable the submit.
- `offerReload` is true only for CONFLICT, which matches UI-SPEC 3f and 3h.

**6. Prefix rule for the Field errors rows**
- The three Field errors rows are returned exactly as the UI-SPEC row reads, without "Nothing was changed.", because they are inline field messages. The test names them as an exception, next to the "Your access" rows, the terminal Failure rows and the outcome-unknown rows.

Scope note: the plan's objective says amendments A1 to A4; A5 (RETRY_RECORDED_NOT_STARTED) was added as the must-have truths and the round-3 orchestrator note require.
