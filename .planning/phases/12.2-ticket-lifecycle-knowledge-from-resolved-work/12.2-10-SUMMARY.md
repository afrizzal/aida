# Phase 12.2 Plan 10: Propose KB article entry points in the ticket menu and the inbox bulk bar Summary

Owners and admins can now start a proposal where resolved tickets live. On a ticket, "More ticket actions" has "Propose KB article…" after "Merge into another ticket…", and it opens `StartProposalDialog` with that one ticket. In the inbox, the bulk bar has the same button after the pickers, and it opens the dialog with the selected ids. Members see neither. When an entry cannot be used it is not hidden. It is disabled with its "Entry unavailable" reason in a 12px muted line, and that line is also its `aria-describedby`. The menu's reasons are AI off, a merged source, and a group other than RESOLVED or CLOSED. The bar's reasons are AI off, more than five tickets selected, and the bar's own call lock or unknown-outcome lock. Both reason orders come from `src/lib/kb/proposal-entry.ts`, which has 16 unit cases.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The disabled menu item's reason could not be heard**
- **Found during:** Task 2 (while checking the repo's aria-disabled precedent for the bulk button).
- **Issue:** Task 1 used Radix `disabled` on the new DropdownMenuItem. Radix removes a disabled item from keyboard navigation, so a screen-reader user can never reach the item, and its `aria-describedby` reason is never read. The repo already fixed the same problem in `status-manager.tsx` (review UI-WR-c1).
- **Fix:** The item now uses `aria-disabled`, with an `onSelect` that calls `preventDefault()` and returns while a reason exists, and `opacity-50`. The reason span is `aria-hidden`, as in the precedent.
- **Files modified:** src/components/tickets/ticket-actions-menu.tsx
- **Commit:** 0b29342

**2. [Interpretation] The bulk helper takes the lock reason, not a lock boolean**
- **Issue:** The plan writes the call as `locked: pending || unknown` (a boolean), and its must-have truth says the helper returns "the bar's existing lock reason". A pure helper in `src/lib/kb` cannot return the bar's text without owning it. The text would then be a new copy row, which the UI-SPEC does not have.
- **Fix:** `locked` is `string | null`. The bar derives it from `pending || unknown` and passes its own text for that lock. The order and the null cases are exactly as the truth states.
- **Commit:** 6fdefc2 (helper), 29e7832 (bar)

**3. [Extra case] A count of 0 returns the too-many row**
- **Issue:** The plan defines no row for 0. The truth only names the too-many row above five.
- **Fix:** A count outside 1 to 5 returns "Select 1 to 5 tickets to propose an article.", so the helper never offers an empty selection. It is unit-tested. The bar renders nothing for 0 selected anyway.
