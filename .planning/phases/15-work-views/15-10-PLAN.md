## Decisions recorded by this plan

The outline fixes this plan's purpose, its owner files and C11; contract section 18.1 fixes the loader reads and the action file. Where they are silent, these choices were made inside 15-CONTEXT (charter rule 4 where privacy or authorization is touched):

1. **Default colour of a new project: gray**, sent explicitly by the Create dialog together with the default icon "folder" (UI-SPEC 3a). The contract's DEFAULT_PROJECT_COLOR (blue) stays the service default for callers that omit `color` (the E2E seed helper, any API caller); the two never conflict because the dialog always sends a colour, so no contract change is needed. Reason for gray: the UI-SPEC is the approved UI contract for the dialog, and gray is the neutral state token, so a new project's colour does not read as a status (blue already marks the ACTIVE project status and the TODO task status in `colors.ts`). This is a technical decision of this plan, not a manual item; the corresponding open line of plan 15-05 is closed by it.
2. **Icon count: 24**, the frozen PROJECT_ICONS. The "25" of the UI-SPEC and the outline is a miscount: Surface 3a names no 25th key, `createProject` refuses any icon outside PROJECT_ICONS (INVALID_INPUT field icon), and adding a key would amend the frozen contract (section 0) and `contract.ts`, which this plan does not own. The 15-05 IconPicker already offers the 24. Technical decision, not a manual item; the corresponding open line of plan 15-05 is closed by it.
3. **Page padding.** The page root is `flex flex-col gap-6` and relies on the (app) main's `p-6`, which equals the UI-SPEC's `px-6 py-6`; no `-m-6` (that is the project shell's need, not the list's).
4. **URL parsing (N6) in this plan's own pure module** `project-list/list-params.ts` (view-query of 15-12 serves the task views; 15-03 allows own strict parsing for the list). Rules: `q` is trimmed, empty is absent, a NUL drops it, and a longer text is cut to its first PROJECT_SEARCH_MAX code points (UI-SPEC Surface 2 "longer input is cut at 80", the same cut the search box applies, so a hand-edited URL behaves like the box); `status` is a comma list whose every part must be a PROJECT_STATUSES value, duplicates collapse, the result is in set order, and any empty or unknown part drops the whole parameter; `archived` is only "only" (anything else is the default "exclude"); `sort` is a PROJECT_SORTS value, else "manual"; a repeated key (an array value) drops that parameter. The canonical URL lists q, status, archived, sort in that order and omits defaults.
5. **Page size** is the service default LIST_DEFAULT (50) for the first page and each Load more (Claude's discretion within LIST_MAX).
6. **Client state survives revalidation, a real reload replaces it.** The results component initializes its loaded pages from props at mount only and is keyed by the canonical query string plus a reload generation. A navigation to another query remounts it; a revalidation re-render after an action does not (so pages appended by Load more and focus survive); an explicit reload (the callout's Reload, or UNKNOWN's reload) runs `router.refresh()` in a transition and, when it ends, bumps the generation and clears the list callout (the reload it asked for is done; UNKNOWN's "AIDA is reloading" would otherwise stay stale).
