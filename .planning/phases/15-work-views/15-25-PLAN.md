## Decisions recorded by this plan

The outline fixes the gate's commands and its record file. Where it is silent, or where the orchestrator's notes for this plan amend it, these choices were made inside 15-CONTEXT and the charter:

1. **depends_on names all 24 plans** (per-plan rule 10): the gate reads every plan's SUMMARY and manual items and runs every plan's tests. All 23 extra entries are transitive dependencies of 15-24 (wave 9), so the wave stays 10.
2. **files_modified is `15-GATE.md` only**, as the outline says. Unlike the outline's "edits no product code", the orchestrator's notes for this plan allow test-harness fixes and, when a gate failure forces it, a recorded product fix with a regression test; every such file is named in the gate-deviation section and the SUMMARY (the verify checks it).
3. **Step names, logs and exit files.** Steps `lint`, `typegen`, `typecheck`, `unit`, `integration`, `e2e`, `build`, `audit`, `cleanroom`, `section9`; each run N writes `${TMPDIR}/aida-15-gate-<step>-run<N>.log` and `.exit`. The two blocked rows have no run.
4. **First pass runs every step** even after a red one (like the Phase 14 gate), so one pass shows every failure; only an environment stop (Docker socket, disk, port, the Rekriva regression) or the `.next/` owner item ends running.
5. **Rerun rule.** The orchestrator's "from the failing step and every later step", plus lint, typegen and typecheck always (they cover every file), plus unit and integration when a fix touched their files. At most two fix attempts per failure and three rerun rounds.
6. **Validity per step.** A step's result stands for the tested commit only when no file that step covers changed after its run (pathspecs in Task 3 Z). This keeps the Phase 14 rule "a result is valid only for the commit it ran on" without rerunning the whole suite after a test-only fix.
7. **PHASE_START** = the parent of the first commit after `40976fd` that changes a file outside `.planning/`, checked to be a plan 15-01 commit.
8. **Audit verdict.** Exit 1 with the baseline counts is "baseline unchanged (not passed)"; changed counts with unchanged package files are "baseline moved by advisory updates" with the delta; a package-file change is red (K78). Never green.
9. **Section 9 step.** An explicit run of the two 15-24 unit proofs gives section 9 its own exit code; the contrast results come from the full E2E log (no second E2E process).
10. **Compose stack not run.** The charter requires `docker compose -p aida up` only at the end of Phases 08, 13 and 17; Phase 15 changes no compose file (grep row). Only two rows are blocked (O-1).
11. **Evidence format.** A test is cited as its path followed by double-quoted titles copied verbatim; a script checks every title against its file, so no row can cite a test that does not exist.
12. **Manual items** are copied, grouped and marked `[open]` with their source plans; the gate closes none of them.
13. **Testcontainers leftovers** are removed only under four conditions (created after the gate start, an aida test image, the node label, no test process of this repository running); anything else is left for the owner (owner rules H and the Larangan on other projects' containers).
