## Decisions recorded by this plan

The outline fixes this plan's purpose, its three proof files and its wave position ("any Phase 15 UI file a proof shows in violation, fix only"). Where it is silent, these choices were made inside 15-CONTEXT (charter rule 4 where a rule could be loosened) and bind 15-25:

1. **Scan scope.** "New Phase 15 files" = every file under the seven D-04 roots plus `src/components/app-nav.ts`, `src/components/ui/sheet.tsx`, `src/lib/projects/colors.ts` (class strings) and `src/lib/projects/ui-copy.ts` (UI text). "Modified Phase 15 files" = `src/components/sidebar.tsx` and `src/app/(app)/layout.tsx` (pre-existing components Phase 15 edited); `src/components/top-bar.tsx` is not edited (owner decision 15-o2 drift check: 15-10 adds its titles to `src/lib/navigation/page-title.ts`) and is checked only by the top-bar rule. Rules about new text (pixel set, weights, `dark:`, sidebar tokens, EmptyState) apply to new files only, so pre-existing 14px nav items, the sidebar's 500 weight and the layout's fallback line stay as they were (UI-SPEC Typography: "14 only inside existing components"; "Existing 500 in the sidebar is untouched"). Every other rule applies to both.
2. **Manifest from the plans.** The appendix lists the 231 UI paths extracted by one rule: every path in the frontmatter `files_modified` of any committed Phase 15 plan that lies under one of the seven D-04 roots or equals one of the six named files (225 under the seven roots, six named files), sorted and de-duplicated; the source is every plan whose `files_modified` holds such a path, not a fixed plan-number range (regenerated at revision 1 over the plans as revised). The test asserts each is scanned; a path changed by a deviation recorded in an executed plan's SUMMARY is adjusted and named in this plan's SUMMARY; a path missing without a recorded deviation is reported to the orchestrator as a gap, never silently dropped.
3. **Token rules beyond the existing literals:** Tailwind palette utilities, arbitrary colour utilities, inline style colours, the brand colour as text (STATE key decision "--primary only as a background"), state utilities outside `colors.ts` (K89), undefined semantic tokens, `dark:` and `sidebar-*` in new files; and the theme token set is pinned at the 45 names of the facts above (D-21: a new token goes into globals.css and into this test; UI-SPEC: no new token in Phase 15). One named exception: the `bg-black/10` scrim of `sheet.tsx`, copied from the vendored dialog overlay as UI-SPEC "New modules" requires.
4. **Weights.** New Phase 15 text uses `font-normal` and `font-semibold` only (UI-SPEC Typography "Two weights for new text: 400 and 600"; Surfaces 2 and 11 give table headers 600). Font families (`font-mono`, `font-sans`, `font-heading`) are not weights.
5. **Empty states as named tables, no blanket allow.** `PAGE_EMPTY_STATES` (each page-level heading and body with the UI-SPEC surfaces where it must be rendered through EmptyState), `MUTED_EMPTY_LINES` ((export name, files, UI-SPEC row or plan decision) pairs where the UI-SPEC specifies a muted line instead) and `EMPTY_VALUE_PLACEHOLDERS` (empty-like names that are field values such as "Unassigned" or "No milestone"). Every ui-copy export whose name looks empty-like is classified in exactly one table, every table name must be an export, and every exception must be used.
6. **EmptyState reachability.** A file satisfies the EmptyState rule when it imports `EmptyState` from the empty-state module, or imports a Phase 15 module that does, or is a non-component `.ts` module imported by a Phase 15 module that does (one hop each way); deeper indirection is not accepted, so a page-level empty state stays visibly wired.
7. **Inline script rule (D-22)** covers script elements, `next/script`, `javascript:` URLs, `eval`, `new Function`, DOM raw-HTML writes (`innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`) and the React raw-HTML prop outside the two sinks. Sink callers are a named allowlist: `ProjectDescription` only in `overview/overview.tsx`; `TaskMarkdownHtml` only in the task-view files that render description, preview or comment HTML (expected `task/task-description.tsx`, `task-view.tsx` if it renders the description itself, and `task/comments-section.tsx`; the set is read from the code and each entry states which renderTaskMarkdown output it passes).
8. **D-04 extension.** The seven roots stay exactly as frozen in section 18.1 (`D04_ROOTS` toEqual). The test adds `D04_EXTRA_FILES` (`src/components/app-nav.ts`, `src/components/ui/sheet.tsx`: new Phase 15 files outside the roots, held to the same rule) and `D04_ANCHORS` (one known file per root), plus the pure `coverageGaps(roots, paths)`. Modified pre-existing files are not added (`src/app/(app)/layout.tsx` imports the database by design).
9. **Clean-room grep is not added to a unit test.** Its literal would then live under `tests/`, which the gate's own grep covers, and it would duplicate the 15-25 gate step. It stays only in 15-25.
10. **Contrast world.** Its own organization through `seedOrganization` (owner "Contrast Owner", member "Contrast Member"); storage state `a11y-contrast-projects-owner`; nothing in the shared E2E organization, so the file-level afterAll and later specs are unaffected. Viewport 1920 x 1400 for every Phase 15 scan (Board, Table, Calendar, Timeline and the workspace pages need the width). One test per page group per theme, not serial, so every failing page reports in one run; a worker restart re-seeds a fresh organization (unique names and prefixes).
11. **Scan hygiene.** Before each scan the pointer is parked at the top-left corner and every finite animation has finished (`document.getAnimations()`), so dialogs and menus are not measured mid-fade and hover styles do not leak into resting-state scans; hover and focus looks stay a manual item.
12. **Fix policy.** A fix changes classes in the owning file only, inside the existing tokens (examples: drop a text opacity modifier, `text-primary` to `text-primary-emphasis`, muted text to `text-foreground` on a tinted surface, `font-medium` to `font-semibold`), never `src/app/globals.css`, never a new token, never a loosened rule, regex or scan, never a skipped test. A violation that needs a token value change is a maintainer decision (DESIGN-SYSTEM section 2 contrast note): stop and report it with the axe data; do not commit a failing test. A copy fix, if ever needed, is a gap row appended to `ui-copy.ts` marked "written by plan 15-24" and pinned in `tests/unit/project-copy.test.ts`.
13. **files_modified** names the three proof files. Product files a proof shows in violation are fixed in place under the outline's 15-24 row; 15-24 is the only plan of wave 9, so no file is shared within the wave. Each such file, its owning plan and its regression spec are listed in the SUMMARY.
14. **depends_on** (charter rule 10) names every plan whose files the scans read or whose pages the contrast run opens: 15-01 (the boundary test), 15-05, 15-06, 15-09 to 15-23.
