## Decisions recorded by this plan

The outline fixes this plan's purpose, files and P2; contract 18.1 and 18.7 fix the reads, URL names and view-state keys; plans 15-12, 15-14 and 15-15 fix the composed blocks. Where they are silent, these choices were made inside 15-CONTEXT (charter rule 4 where privacy or authorization is touched):

1. **Workspace loader module** `src/lib/project-ui/load-workspace-frame.ts` (deviation: a new file outside the outline list; no plan names it): one place for the 18.1 workspace reads so plan 15-22 reuses it for CALENDAR and TIMELINE. It parses the URL, then reads `getWorkspaceViewState`, every page of `listProjects` (current projects) and `listWorkspaceTasks({ groupCounts: "assignee", limit: 1 })` without filters (N5).
2. **Unreadable project ids are dropped in the loader.** `?project=` ids that are not among the reader's current readable projects are removed before any task read; a missing, an archived and an unreadable id take the same path, so nothing reveals existence (K74, D-06), and no chip ever needs a name for a project the reader cannot see. If none remain, the project filter is absent. This is N6's rule ("an invalid parameter is dropped") applied per id; the service keeps its own "matches nothing" rule for direct calls.
3. **No saved views and no notices at workspace level** (D-17 scopes saved views to projects; 15-12 decision for workspace loaders). Assignee options come from readable tasks (N5), so a person without a visible task is not "stale"; such a filter value matches nothing and its chip reads "Someone" (N2 fallback). No stale notice is shown.
4. **Form switch** in the toolbar's `end` slot of each form. The frame's resetKey is `workspace|{KIND}|none`, so a form change remounts the frame; the switch records the requested form in a module-level variable and the newly mounted switch focuses its pressed segment (Focus row "Form switch: stays on the pressed segment"). Segments are text buttons with icons (`List`, `SquareKanban`, `Table2`) labelled from WORKSPACE_TASK_FORM_LABELS, the archive-scope pattern of 15-10.
5. **Per-form persistence** is the rows LIST, BOARD and TABLE with projectId null (P2, C2); the form itself lives only in the URL.
6. **Workspace Board footer holds only Load more** (deviation from 15-14's hand-off "omit footer", which assumed the footer is quick add only): D-11's per-column keyset Load more applies to the workspace Board as well, so a column with more than 50 cards stays reachable; there is no quick add at workspace level (UI-SPEC researcher choice 10).
7. **Drop feedback.** A drop target in the dragged card's own column shows no indicator and sends nothing; an expanded other column shows the 15-14 indicator line at the pointer's insertion index; a collapsed column shows the line at its top. The card lands where the due-date order puts it, as the board note says.
