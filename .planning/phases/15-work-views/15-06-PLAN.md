## Decisions recorded by this plan

The outline fixes this plan's files, owners and purpose, and section 18 of plan 15-01 fixes the date semantics; this plan uses them exactly. Where they are silent, these choices were made inside 15-CONTEXT (Claude's discretion: component and file layout and exact names; charter rule 4 where behaviour could surprise a user) and bind the consuming plans:

1. **Two extra test files** (deviation from the outline file list; `grep` over every committed and outlined Phase 15 plan shows no other owner): `tests/unit/project-move-ui.test.ts` proves the pure parts and the server-rendered markup of the three components (the unit config runs `.ts` files in node with no DOM, so their pointer and keyboard behaviour is proven by the E2E of the consuming plans); `tests/integration/project-move-kit.test.ts` is the tracer that sends the kit's arguments through the real `reorderTask` and `setTaskDates`, because this plan has no route and the anchor rule of C4 is only proven when the real group semantics (moved task excluded, archived tasks included) agree with it.
2. **The truly last card**: on the last card of a fully loaded column (or the last subtask), Move down is left out of the menu. No position exists below it, the Copywriting Contract has no reason row for it, the disabled-with-reason convention [P12] cannot be met without copy, and only plan 15-05 owns the copy module. This is a decided limit (run decision K98, finding S2-I2), not a manual item.
3. **Status in Board arguments**: moves inside one column (Move up, Move down, Move to top, a same-column drop) send no status, so a stale view is refused (INVALID_INPUT field placeAfterTaskId, which the Board move refused copy describes) instead of silently moving the card back to the column the user saw; Move to {status} and a cross-column drop send the target status. Menu and drop send identical arguments for the same intent (D-14).
4. **Subtask arguments** never carry a status and are computed over `getTask`'s full subtask list (no paging, so no NEEDS_LOAD).
5. **Grid days**: calendar-date accepts any real date written YYYY-MM-DD with a year from 1000 to 9999, wider than the stored range, because the month grid of January 1970 starts on 1969-12-29 and that of December 2999 ends on 3000-01-05. `serviceWindow` clamps the window sent to a service; `calendarStep` and `timelineStep` clamp the next URL date into the stored range; a shift result outside the stored range is sent unchanged and the service refuses it (18.6: "decided by the service").
6. **No reuse of `addDays`** from recurrence-rules.ts: it throws outside the stored range (point 5). calendar-date writes its own whole-day UTC arithmetic over the contract helpers.
7. **Unavailable menu items stay focusable** (aria-disabled with a described reason, not the Radix disabled prop), choosing one does nothing, and the menu moves focus to the first available item on open (UI-SPEC Focus table "Move menu opens").
8. **Dialog items** (Set date, Set dates) call the view's `onSelect` from the menu's close-focus handler with the default focus return prevented, so the dialog keeps focus; the view returns focus to the Move button through `focusMoveButton` when that dialog closes without acting.
9. **Drag mechanics**: listeners sit on `window` from pointer down to idle; no pointer capture, so a press and release without movement is an ordinary click on the title link; the native drag of links and images is prevented; the click right after a started drag is swallowed once; touch-action is not overridden, so touch panning still scrolls and a pan cancels the drag with `pointercancel` (touch-specific drag is deferred in 15-CONTEXT).
10. **Release outside every drop target** cancels with reason `outside`; consuming views announce it like Escape.
11. **Announcer**: each announcement empties the region and writes the text 100 ms later, so a repeated text is announced again and a newer text replaces a pending one.
12. **Display**: one lazily created en-GB formatter per style with timeZone UTC; ranges use an en dash with spaces; announcements and bar labels use the full style.
13. **Move ids**: Board `status:{STATUS}`, `up`, `down`, `top`; subtask `up`, `down`, `top`; Calendar `earlierDay`, `laterDay`, `earlierWeek`, `laterWeek`, `setDate`; Timeline the same four shifts and `setDates`.
14. **Import rule**: calendar-date.ts and move-anchors.ts sit in `src/lib/projects/`, which the operation inventory scans, so they use relative imports only and import nothing from Next.js (outline convention 9). The worker reads neither module, but the directory rule applies to every file there. The three components are app-only client components; they import the UI wrappers through the repository path alias like every other component, and the D-04 boundary scan resolves that alias.
15. **Month-zoom window and step (run decision K96, findings S2-W4 and S7-B1).** Every Timeline window starts on a Monday (18.6), so consecutive windows can only tile (no gap, no overlap) when every window is a whole number of weeks; 12 calendar months are 365 or 366 days, never a multiple of 7, so the first draft's month window (start to the day before the date 12 calendar months later) and its step (twelve months, then back to the Monday on or before) left 2026-11-03 to 2026-11-08 unseen when paging back from 2026-11-09 and showed one day twice when paging forward. Rule chosen: the month-zoom window runs from its Monday start to `endOfWeek` of the day before `addCalendarMonths(start, TIMELINE_WINDOWS.month.months)`, which for every Monday start is exactly 53 weeks (371 days) and always contains the 12-calendar-month window 18.6 describes; `timelineStep` moves the normalized start by exactly the window's length in days at every zoom (28, 112, 371), which is 18.6's "previous and next shift the start by one window" taken literally. `defaultTimelineStart` is unchanged (a Monday, so its window starts on it) and 371 stays below TASK_WINDOW_MAX_DAYS (400). The contract constant `TIMELINE_WINDOWS.month = { months: 12 }` of plan 15-01 is used unchanged; only the window end is rounded up to the end of its last week, as the Calendar month mode already rounds to whole weeks. Tiling holds wherever the unclamped step stays inside 1970-01-01 to 2999-12-31; at those edges the clamp of decision 5 wins (Next at the end of the range keeps the last window). Exact values from 2026-11-09: window 2026-11-09 to 2027-11-14; next 2027-11-15 (window 2027-11-15 to 2028-11-19); previous 2025-11-03 (window 2025-11-03 to 2026-11-08). From the default start of today 2026-11-10 (2026-11-02): window 2026-11-02 to 2027-11-07; next 2027-11-08; previous 2025-10-27 (window 2025-10-27 to 2026-11-01).
