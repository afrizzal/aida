Rules (charter and ROADMAP):
- One test process at a time; long commands write to a log under a `mktemp -d` directory in `${TMPDIR}`; read each exit code without a pipe.
- If `tsc` or the build breaks after repeated E2E runs because of truncated `.next/dev/types`, delete the gitignored `.next/` and rerun.
- Audit: record plain `pnpm audit --prod` as is (non-zero while any advisory remains); the security bar is `--audit-level=high`; a residual high or critical is `failed` (red) with its reason, never passed. Network failures are `blocked (with evidence)`.
- Compose gate: if port 80 or 443 is in use, do not stop other services; record `not run` (parked) with the process name. Never stop, remove or change containers or volumes outside project `aida`, `aida-dev-db` and the per-run test projects the suites themselves create and remove. `docker compose -p aida down` without `-v`.
- Image builds can stall at an external host; record `blocked (with evidence)`, never use a mirror.
- `RUN-LOG.md`, `LAPORAN.md`, `ANTREAN.md` and `REQUIREMENTS.md` belong to the orchestrator; this plan does not edit them. The orchestrator writes the release safe point into LAPORAN.md from this gate file.
- The compose gate reads the operator's existing `.env` (never edits it). If required values are missing, record the check as `blocked (with evidence)` with the variable names (not values).
- Result vocabulary (review C5): `passed`, `failed`, `blocked (with evidence)`, `not run`. The verify scripts below read these words.
- Container suites print one `CONTAINER-SUITE-RESULT` line each with the stack state (`ready`, `blocked`, `failed`); failures start with `BLOCKED:` or `FAILED:` (plan 08-14). The production E2E has projects `production-host` and `production-caddy`; a blocked Caddy topology fails with `BLOCKED:` (plan 08-21).
