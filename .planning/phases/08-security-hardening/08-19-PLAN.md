## Recording rule for `pnpm test:egress` (cycle-4 brief, known blocker)

The cycle-4 brief says that until the owner adds space, every step that builds images stops at the rule J preflight, and plans record this as `blocked (space)`, never as passed. This plan does not run `pnpm test:egress`. The rule is written here, next to the guard that pins the message it keys on. It applies to every row in this phase that records a `pnpm test:egress` run: the orchestrator's 0a2 baseline, plan 08-16's gate (whose reporter comes from plan 08-14), and the report of plan 08-05's CI `egress` job.

1. A suite file's result is `blocked (space)` only when all of these hold:
   - the run's exit code is non-zero;
   - the log contains a line matching `Free space on (the host|the Docker VM) is [0-9.]+ GiB, below the 20.0 GiB rule J requires before an image build` (the `assertEnoughSpace` text in tests/support/docker-test-preflight.ts, pinned by Task 1);
   - no test of that file passed;
   - the log shows no other error for that file.

   The Note quotes the matched line.
2. A space stop is never `passed` and never `not run`. A space stop together with another error is `failed`, with both quoted.
3. Any other `DockerPreflightError` stop gets the existing word `blocked (with evidence)` and quotes its line. That covers a held lock, an existing project, network, volume or tag, a subnet overlap, and free space that cannot be read.
4. Nothing is removed, pruned or stopped to make room. Freeing or adding space is the owner's call (queue item 0a2, options a to d); rule J says stop and report.
5. Worked case, 0a2 round 1 (2026-11-11): exit 1 in 11 s, "Free space on the Docker VM is 13.9 GiB, below the 20.0 GiB rule J requires", 4 tests skipped, 0 passed, nothing created or left behind. Result: `blocked (space)`.
