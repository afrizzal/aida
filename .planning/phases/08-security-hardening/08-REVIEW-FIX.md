K128, K129 and K130, as implemented:
- **K130, pool and transaction setup found.** `src/lib/db.ts` builds `pg.Pool({ max: DB_POOL_MAX || 10 })` behind `@prisma/adapter-pg` 7.8.0. `connectionTimeoutMillis` is not set, so pg-pool queues a connect with no time limit. The limiter ran `prisma.$transaction(..., { maxWait: 5000, timeout: 5000 })`. In Prisma 7.8.0, `maxWait` covers the driver adapter's `startTransaction()`, which includes the pool connect. When it passes, Prisma throws P2028 "Unable to start a transaction in the given time" and later rolls back the connection once it arrives. The advisory-lock wait ran inside the transaction with no `lock_timeout`, so it was bounded only by the 5 s transaction `timeout`, and that timeout surfaced as a P2028 error, which the routes turn into a 500.
- **K130, fix.** The limiter sets a transaction-local `lock_timeout` of 500 ms (`set_config('lock_timeout', ..., true)`) and `maxWait` 1000 ms. A lock timeout (SQLSTATE 55P03, which Prisma reports as P2010 with `meta.driverAdapterError.cause.originalCode`) or the P2028 start timeout returns "not allowed" with Retry-After 1 (`RATE_LIMIT_BUSY_RETRY_AFTER_SECONDS`). The routes answer 429 and no hit is recorded. The values are `RATE_LIMIT_LOCK_TIMEOUT_MS` and `RATE_LIMIT_POOL_WAIT_MS` in `src/lib/rate-limit/check-rate-limit.ts`.
- **K128.** `MAX_FILES_PER_REQUEST = 10` in `src/lib/attachments/constants.ts`. Neither shipped public form sets a count (the request form's `<input type="file" multiple>`, and the follow-up form, which appends files with no limit), so the cap is K128's default of 10. `validateUploadFiles` checks the count before it reads any file and answers 413 `too_many_files`.
- **K129.** `PUBLIC_TEXT_LIMITS = { name: 200, email: 320, subject: 500, message: 50 000 }` in `src/lib/attachments/constants.ts`, next to the byte caps. No existing limit covers these fields: the agent composer (`src/app/api/tickets/[id]/messages/route.ts`) checks only that a reply is not empty, the email ingest (`src/lib/channels/email/ingest-message.ts`) caps attachments but no text, and the columns (`Contact.name`, `Contact.email`, `Ticket.subject`, `Message.bodyMarkdown`) are unbounded `text`. The values are therefore K129's defaults. The other zod limits in the code belong to other fields: the CSAT comment (2 000), list filters (200) and the KB proposal prompt truncation (subject 300, message 4 000 code points). The lengths are UTF-16 code units, as zod and the browser count them. One module, `src/lib/public-forms/limits.ts`, holds the schemas and the plain-English copy for both routes and both forms. The triage prompt is not truncated (deferred by K129).

### Deviations and notes

- **K130 residual.** `maxWait` bounds how long a limiter call waits for a connection. The abandoned pool connect stays in pg-pool's queue until a connection frees, and Prisma then rolls it back at once, so it costs one BEGIN and ROLLBACK. A pool-wide `connectionTimeoutMillis` would bound that queue too, but it would change the behaviour of every query in the app, which is outside K130, so it was not set. The over-quota path still costs a full transaction (count, lookup, commit), as the review notes; that is unchanged.
- **K130 test seam.** `rateLimitLockKey()` and `setRateLimitLockObserverForTests()` are new exports of `check-rate-limit.ts`, the same seam pattern as `setCsatWriteObserverForTests`. Production never sets the observer.
- **K128 commit and the E2E specs.** The two E2E specs carry the K128 and the K129 form checks, and the status-page test covers both in one case. They are committed with K129 (0d86f5a), after the green E2E run. The K128 commit (aafc8de) was verified by its integration cases. Its test file was committed without the K129 block, which followed in 0d86f5a.
- **Form copy.** The follow-up textarea gained `aria-label="Follow-up message"`, plus `aria-invalid` and `aria-describedby` pointing at its new error line. The error lines use the existing `text-[12px] text-destructive` pattern, so there are no new tokens. Design checklist (DESIGN-SYSTEM.md section 9): no new token, explicit `text-[Npx]` sizes, `tsc` clean. Dark mode is a manual item and was not checked.
- **E2E server answers.** The forms' handling of the server's 413 `too_many_files` and 400 field errors is tested by fulfilling the POST with `page.route`, because the client checks stop such a request before it is sent. The route-level answers themselves are proven by the integration cases.
- **Placeholder secrets.** IN-b7 also suggested checking the other `replace-me` secrets. Only `RATE_LIMIT_PEPPER` is checked, as the disposition says.
