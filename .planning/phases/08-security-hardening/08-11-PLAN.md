## Docker health rule (review R2-2)

A Docker step is any step that needs the Docker daemon: Testcontainers (through `pnpm test:integration`, `pnpm test:e2e` or `pnpm test:e2e:prod`), the `aida-dev-db` container, an image build, or a compose stack. `docker compose ... config` renders without the daemon and is not a Docker step.

1. Immediately before the first Docker step of each task, run `colima status` and then `docker info` as two separate commands and read each exit code without a pipe.
2. If either exits non-zero or prints an error: never stop, restart or delete Colima or Docker (charter owner rule B); skip every remaining Docker step of this plan and every step that needs a Docker result; record each skipped step and each skipped Docker verify command in the SUMMARY as `blocked (docker unhealthy)` with the output of both commands; finish and commit only the remaining work that needs neither; then stop this plan and end the SUMMARY and the final report with the line `DOCKER-UNHEALTHY: <command> exit <code>`, so the orchestrator applies charter rule B and "Berhenti total".
3. A `blocked (docker unhealthy)` step is never recorded as passed or failed, and its verify command is not run.
