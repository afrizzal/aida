<objective>
Throttle `/api/health` and cap its database load without breaking the container healthcheck (D-20, AIDA-30, F-12): an in-memory per-identity throttle with a bounded shared bucket, and a 3-second cache with single-flight for the database read. Wave 3 content per D-30 (wave 8 here); it reuses the identity helper (08-10) and the 429 helper (08-11). The container healthcheck's own unthrottled path is plan 08-20 (review C2), which builds on `readHealthSnapshot()` from this plan.

Purpose: the endpoint is public and hits the database on every request. A DB-backed limiter would add the load it is meant to prevent, so this one lives in memory (per process by design, no Redis).
Output: a throttle module, a health module, the rewritten route, tests for DB down and up, concurrency, a flood and the healthcheck, and updated docs.
</objective>
