## Typography

Sizes used by **new** elements in this phase (4 sizes, 2 weights):

| Role | Size | Weight | Line height | Where |
|------|------|--------|-------------|-------|
| Caption | 12px (`text-[12px]`) | 400 (600 in the count pill) | 1.5 | Emails under names, relative times, role help text, bell row second line, count pill digits |
| Body / label | 13px (`text-[13px]`) | 400 / 600 | 1.5 | Member names (600), row text, bell row sentence (600 when unread, 400 when read), preference row labels, callouts, admin-only notices, dialog descriptions |
| Section heading | 15px (`text-[15px] font-semibold tracking-tight`) | 600 | 1.2 | `<h2>` card titles "Members", "Pending invitations", "Event types"; bell popover title (a `<p>`, not a heading) |
| Page title | 18px (`text-[18px] font-semibold`) | 600 | 1.2 | Visible `<h1>` "Team" and "Notifications", invite-page and no-access card titles, EmptyState heading [DS §3] |

- **Caption vs body are separated by colour as well as size [RL, carried from 09-UI-SPEC].** 12px caption is always `text-muted-foreground` (the count pill is the one exception: `text-primary-foreground` on `bg-primary`). 13px body is `text-foreground` for content (names, bell sentences, preference labels) and `text-destructive` inside destructive callouts; 13px is muted only for page subtitles and admin-only notices, which never sit beside a 12px caption.
- Weights: 400 and 600 only for new elements. Existing 500 (`font-medium`) on settings tabs is untouched.
- 14px stays where it already is (nav items, composer textarea, EmptyState body); no new 14px text is introduced.
- Explicit `text-[Npx]` only; never `text-sm` / `text-lg` / `text-xl` [DS §3, §8 rule 6]. Where a shadcn component ships `text-sm` internally (Select item, Command item, Dialog description), the executor overrides it with `text-[13px]` on the instance.
- The copyable invitation link renders in `font-mono text-[12px]` inside a read-only Input (identifier) [RL].

## Surface 1 — Settings → Team (`/settings/team`)

Navigation: `SettingsNav` gains `{ href: "/settings/team", label: "Team" }` and `{ href: "/settings/notifications", label: "Notifications" }`, appended in that order after "Email" [RL]. Top-bar title stays "Settings" (existing `/settings` prefix rule).

Page (`space-y-6`, inside the existing settings layout):

1. Header row `flex flex-wrap items-start justify-between gap-4`:
   - Left (`space-y-1`): `<h1 className="text-[18px] font-semibold">Team</h1>` + 13px muted subtitle "People in this workspace and the role each one has."
   - Right (owners and admins only): **Invite member** (`Button` default, `UserPlus` icon `size-4`) → opens the Invite dialog.
2. **Members card** `Card className="border-border/70 p-4 shadow-sm"`, `space-y-4`:
   - `<h2 className="text-[15px] font-semibold tracking-tight">Members</h2>` followed by a 13px muted count "{N} people" / "1 person".
   - Non-admin notice (role `member`): 13px muted line "Only workspace owners and admins can invite people or change members."
   - `<ul className="divide-y divide-border/70">`; each `<li>` is a row `flex flex-wrap items-center gap-4 py-2`:
     - Identity block `flex min-w-0 flex-1 items-center gap-2`: Avatar `size-8` (initials) + stack `min-w-0 space-y-1`: name `truncate text-[13px] font-semibold text-foreground`, email `truncate text-[12px] text-muted-foreground`. The signed-in user's row adds a `Badge variant="outline"` "You".
     - Role control: an editable `Select` (`h-8 w-[120px] text-[13px]`, `aria-label="Role for {name}"`) when the actor may change this row; otherwise a `Badge variant="secondary"` with the role label.
     - Actions (only when the actor may deactivate this row): ghost `Button size="sm"` with `UserMinus` icon, label "Deactivate member", `className="text-destructive"`.
   - Sort: owners, then admins, then members; inside a role, by name (case-insensitive) [RL].
3. **Pending invitations card** (owners and admins only), same card classes, `space-y-4`:
   - `<h2>` "Pending invitations".
   - None: 13px muted line "No pending invitations." (not an EmptyState: the page is never empty, the actor is always a member).
   - Rows as above: identity block shows the invited email (13px, 600) and a 12px muted line "{Role} · invited by {inviter name} · expires {relative time}"; action: ghost `Button size="sm"` `X` icon "Revoke invitation", `text-destructive` → Revoke dialog.
   - Accepted, revoked and expired invitations are not listed [RL].

Who may do what (UI mirrors D-03/D-09; the server is authoritative):

| Actor → target row | Role control | Deactivate |
|--------------------|--------------|------------|
| Any actor → own row | Badge only (nobody changes their own role) | Hidden |
| Member → any row | Badge only | Hidden |
| Admin → member/admin row | Select with options Member, Admin | Shown |
| Admin → owner row | Badge only; Tooltip on the badge "Only an owner can change another owner." | Hidden |
| Owner → any other row | Select with Member, Admin, Owner | Shown |
| Owner → the last remaining owner (only reachable as own row) | Badge only | Hidden |

Interaction contract:
- **Role change** saves on selection (no Save button). While pending the Select is disabled and shows the new value; success → `toast.success("{Name} is now {role}.")`; failure → the Select reverts to the stored role and an inline destructive callout appears at the top of the Members card with the matching Copywriting error, `role="alert"`, cleared on the next change.
- **Deactivate** opens the Deactivate dialog (Copywriting). When the target has open assigned tickets, the dialog shows a 13px line "{Name} has {N} open tickets assigned." and a `Select` labelled "Reassign their open tickets to" with options "Keep them assigned" (default) and every other current member by name [CTX D-07: offered, never forced]. Confirm button (destructive) shows `Loader2 className="mr-2 size-4 animate-spin"` and "Deactivating…" while pending; success closes the dialog, removes the row, fires `toast.success("{Name} was removed from the workspace.")`; failure keeps the dialog open with the error as a 13px `text-destructive` line, `role="alert"`, above the footer.
- **Revoke** opens the Revoke dialog; same pending/success/failure pattern ("Revoking…", toast "Invitation revoked.").
- Rows update through `revalidatePath("/settings/team")`; no optimistic row removal.
- Keyboard: Select and buttons are native radix controls; dialogs trap focus and return it to the trigger (radix default); after a row is removed, focus moves to the Members `<h2>` (`tabIndex={-1}`) [RL].
- Narrow screens (< 640px): `flex-wrap` moves the role control and the action under the identity block; nothing scrolls horizontally.

### Invite dialog

`DialogContent` (default width), `space-y-4`:
- Title "Invite a member"; description (13px muted) "They get an email with a link that works for 7 days. They join with the role you pick here." [CTX D-04: 7 days].
- Field **Email** (`Input type="email"`, `autoComplete="off"`, required).
- Field **Role** (`Select`, default "Member"); options capped by the actor: admins see Member, Admin; owners see Member, Admin, Owner [CTX D-03]. Help text (12px muted, `aria-describedby`): "Admins can invite people and change members. Only owners can add or change owners."
- Footer: "Close without sending" (outline) and **Send invitation** (default, `Send` icon). Pending: spinner + "Sending…", both fields disabled.
- Outcomes:
  - **Email accepted by SMTP:** dialog closes, `toast.success("Invitation sent to {email}.")`, the pending list refreshes.
  - **SMTP not configured, or the send failed:** the dialog stays open and switches to a result view: warning callout (`flex items-start gap-2 rounded-lg border border-warning/30 bg-warning/10 p-4 text-[13px] text-warning`, `TriangleAlert size-4 shrink-0`) with the matching Copywriting notice; below it a read-only `Input` (`font-mono text-[12px]`, `aria-label="Invitation link"`, selected on focus) and a **Copy link** button (outline, `Copy` icon; after copying, label "Copied" with `Check` icon for 2 seconds, `aria-live="polite"`). Footer: "Return to team" (default), which closes the dialog. The link is shown only here, only to owners and admins, and never again after the dialog closes [CTX D-06; RL "shown once" because the stored token may be hashed per D-04].
  - **Validation or server error:** inline destructive callout above the footer, `role="alert"`, fields keep their values.
- The link's base URL is configuration-derived (server), never built in the client [CTX D-06].

## Surface 2 — Invitation page (`/invite/[token]`)

Route lives in the `(auth)` group (`src/app/(auth)/invite/[token]/page.tsx`) so the auth layout supplies the dotted grid and brand glow; the page renders only a `<Card className="w-full max-w-[400px] border-border/70 shadow-xl shadow-primary/5">` [DS §4.4, §8 rule 4]. The planner checks that the `(auth)` layout does not redirect signed-in users away from `/invite`; if it does, the redirect excludes `/invite`. Response header `Referrer-Policy: no-referrer`; no external resource and no inline script on the page [CTX D-04, Domain]. Exactly one `<h1>` per state (the card title).

States (server decides; the token is never echoed in the page text):

| State | Card content |
|-------|--------------|
| Valid, signed out, no account for the invited email | `<h1>` "Join {workspace name}"; 13px muted "You were invited as {role}. Create your account to join."; form: **Name** (Input), **Email** (Input `readOnly`, value fixed to the invited address, `aria-readonly`), **Password** (Input `type="password"`, help 12px muted with the existing minimum-length rule); button **Create account and join** (full width) |
| Valid, signed out, account exists for the invited email | `<h1>` "Join {workspace name}"; 13px muted "You were invited as {role}. Sign in to join."; form: Email (read-only, fixed), Password; button **Sign in and join** (full width). The token stays on this page; no redirect to `/login` carries it [RL] |
| Valid, signed in, email matches | `<h1>` "Join {workspace name}"; 13px muted "You were invited as {role}. You are signed in as {current email}."; button **Accept invitation** (full width) |
| Valid, signed in, email differs | `<h1>` "This invitation is for a different email"; 13px muted "You are signed in as {current email}. Sign out, then open the invitation link again."; button **Sign out** (outline, full width). The invited address is not shown. Nothing is accepted [CTX D-05] |
| Invalid, expired, revoked, already used, or any accept-time check fails | `<h1>` "This invitation link is not valid"; 13px muted body per Copywriting; link-style button "Go to sign in" → `/login`. One generic message for every failure kind, so nothing about other organizations or the token's history is revealed [CTX D-03; RL] |

Interaction contract:
- Every submit shows the button spinner + pending label ("Creating account…", "Signing in…", "Joining…") and disables the form.
- Field errors render under the field as 12px `text-destructive` (existing `FormMessage`); a server failure that is not a field error renders as the destructive callout above the button, `role="alert"`.
- Success (all three paths) → redirect to `/tickets` with the active organization set, then `toast.success("Welcome to {workspace name}.")`.
- A wrong password on "Sign in and join" shows the existing login error copy; no accept happens.

## Surface 3 — Notification bell (top bar)

Placement: `TopBar` right cluster becomes `NotificationBell`, `ThemeToggle`, `UserMenu` (existing `flex items-center gap-2`). The header keeps `sticky top-0 z-10 … backdrop-blur-sm border-border/70` unchanged [DS §4.2, §8 rule 5].

Trigger: `Button variant="ghost" size="icon" className="relative size-8"` with `Bell size-4`.
- `aria-label`: "Notifications, {N} unread" when N > 0, else "Notifications".
- Count pill (N > 0 only): `Badge` `absolute -top-1 -right-1 h-5 min-w-5 justify-center rounded-full border-transparent bg-primary px-1 text-[12px] font-semibold text-primary-foreground`, `aria-hidden` (the label carries the number). Shows 1–9, then "9+".
- Count = unread and not archived for this member in the active organization [CTX D-19].

Popover: `PopoverContent align="end" className="w-[360px] p-0"`, labelled by its title.
- Header `flex items-center justify-between px-4 py-2`: `<p id=… className="text-[15px] font-semibold tracking-tight">Notifications</p>` + ghost `Button size="sm"` "Mark all read" (`CheckCheck` icon), disabled when N = 0. Then `Separator`.
- List `<ul className="max-h-[420px] overflow-y-auto">`, newest first, the 20 most recent non-archived notifications [RL]. When more exist, a footer 12px muted `px-4 py-2` line "Showing the 20 most recent." (the full notification center is AIDA-83, Phase 16).
- Row `<li className="group flex items-start gap-2 px-4 py-2">`, unread rows `bg-muted/40`:
  - Unread dot `mt-2 size-2 shrink-0 rounded-full bg-primary` (read: an invisible `size-2` spacer so text aligns).
  - Type icon `mt-1 size-4 shrink-0` (4px top offset for alignment): `UserCheck` assigned, `MessageSquare` customer reply, `AtSign` mention (all `text-muted-foreground`), `Clock` SLA at risk (`text-warning`), `TriangleAlert` SLA breached (`text-destructive`).
  - Text block `min-w-0 flex-1 space-y-1`, wrapped in a `Link` to the ticket (`/tickets/{id}`) that covers the text block: line 1 = Copywriting sentence, 13px, `font-semibold` when unread, `font-normal` when read; line 2 = 12px muted `truncate` "{ticket subject} · {relative time}" (`<time dateTime>`). The subject renders as escaped text, never HTML.
  - Actions `flex shrink-0 gap-1`: unread only → ghost icon `Button size-8` `Check` "Mark as read"; always → ghost icon `Button size-8` `Archive` "Archive notification". Both have `aria-label` and a Tooltip with the same words.
- Clicking the row link marks it read, closes the popover and navigates.
- Archive removes the row from the list and the count immediately after the server confirms (row fades out with `transition-opacity`, honouring `motion-reduce:transition-none`); read state persists across reloads [CTX D-19].

Data and polling [CTX D-19; interval RL]:
- Poll the unread count every **30 seconds** while the tab is visible (`document.visibilityState === "visible"`); pause when hidden, refetch once on becoming visible. No websocket, no "live" or "real-time" wording anywhere.
- Opening the popover fetches the list fresh. The count also refetches after any mark-read / archive action.
- A failed poll keeps the last known count silently and retries at the next interval; it never shows an error on the trigger.

States inside the popover:

| State | Render |
|-------|--------|
| First load | 3 `Skeleton` rows (`h-12` each, `mx-4 my-2`) |
| Empty (no non-archived notifications) | Compact EmptyState: `<EmptyState icon={BellOff} heading=… body=… className="min-h-0 py-8" />`; halo + icon box classes unchanged [DS §4.3]. `EmptyState` gains an optional `className` merged with `cn()` on its root; no other prop or class changes |
| Load failed | Destructive callout `mx-4 my-2` with the Copywriting error and a ghost `Button size="sm"` "Try again", `role="alert"` |
| Action failed (mark read / archive / mark all) | Same callout above the list; the row keeps its previous state |
| Populated | Rows as above |

## Surface 4 — Mentions (internal-note composer and thread)

Composer (`composer.tsx`, internal mode only) [CTX D-20, D-21]:
- Typing `@` at the start of the textarea or after whitespace opens `MentionAutocomplete`: `Popover` anchored to the composer wrapper, `PopoverContent align="start" className="w-[280px] p-0"`, containing `Command` with `shouldFilter` on the query typed after `@`.
- Options: current members of the active organization only, served through the D-08 membership helper; each `CommandItem` = Avatar `size-8` + stack name (13px, 600) and email (12px muted). Max 8 visible, `max-h-[288px]` scroll [RL]. The signed-in author is not listed (mentioning yourself has no use) [RL].
- Keyboard: ArrowUp/ArrowDown move, Enter or Tab inserts, Escape closes and leaves the typed text; focus stays in the textarea (`aria-activedescendant` on the textarea, `role="combobox"` / `aria-expanded` / `aria-controls` wired to the list).
- Insert: replaces `@query` with `@{Name} ` and records the member id in client state. Deleting any character of an inserted `@{Name}` drops that id. Only ids are sent as structured data next to the body; the body never contains an email [CTX D-20].
- Public mode: typing `@` opens nothing. Switching from internal to public with recorded mentions removes each inserted `@{Name} ` from the text (plain `@text` the agent typed stays), clears the ids, and shows a 12px muted line under the textarea: "Mentions only work in internal notes. The mentioned names were removed from this reply." (changed in plan review round 1, C7: an inserted member name must never reach a public body) It disappears on the next switch back or on send.
- Member list loads once per composer mount; while loading, the list shows one `Skeleton h-8 mx-2 my-2`.

Thread rendering (`thread-message.tsx`, through `renderMarkdown` only, no raw HTML) [CTX D-20]:
- A stored mention renders as `<span className="font-semibold text-primary-emphasis">@{Name}</span>` (the sanitizer allowlist gains exactly this span with this class, nothing else). No link, no email, no hover card.
- A mention of someone who is no longer a member renders the same span (history unchanged); no notification is created for them (server rule).
- Plain `@text` in any PUBLIC message renders as plain text.
