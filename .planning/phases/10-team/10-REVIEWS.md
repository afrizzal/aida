### Required properties for the replan

- **C1:** 10-14 does not run `pnpm test:egress`, and does not run the egress file inside `pnpm test:integration`, while O-1 is pending; both are recorded as "blocked (O-1)", never as passed. The rest of the integration suite runs with the egress file excluded by an explicit, recorded command, plus every Phase 10 integration file by name.
- **C2:** `acceptInvitation` resolves the organization from the token hash, then takes the same organization row lock as 10-03, re-reads the invitation and the inviter inside that lock, and accepts in the same transaction; revoke uses the same lock order. A barrier test forces accept to interleave with a demotion and with a deactivation of the inviter.
- **C3:** the replan states the invariant explicitly (at least one owner, per D-09's rules) and reconciles D-09's "count owners and admins" and its "last two admins" test with it; the concurrency tests use two connections and a barrier (for example an advisory lock or a hook held after the lock is requested) so the second transaction provably waits on the organization lock.
- **C4:** the executor lists the organization plugin routes from the installed 1.6.22 package; every endpoint left open has an HTTP-level test (with and without a cookie, with a stale cookie after deactivation, and selecting another organization) proving it cannot bypass D-03, D-08 or D-09; any endpoint without such a test is closed.
- **C5:** the inventory works per function and follows calls from pages and actions into `src/lib` helpers that reach tenant data, with a written reason for every exemption; the worker and the public status token path state their own authorization rule; negative tests cover a helper-mediated page, an action, an API route, the attachment route, a worker job and the public token page.
- **C6:** every protected render entry point under `(app)` uses the page helper that turns `AccessDeniedError` into the `/no-access` redirect, and the inventory enforces it; an E2E or integration test opens several pages with a revoked membership and lands on `/no-access`.
- **C7:** an internal-to-public switch removes the inserted mention text (or keeps the internal draft separate) so no inserted member name reaches a public body; the switch-note copy in UI-SPEC is updated to match; tests cover the public message body, the status page and the outgoing SMTP message after a mode switch. Plain `@text` typed in a public reply stays allowed (D-21).
- **C8:** the docs state that an ambiguous SMTP outcome (accepted but no reply) can produce one duplicate; the fake SMTP gets a fault that accepts DATA and drops before replying, and that case keeps the batch until the lease expires instead of releasing it at once; the re-check runs after the `beforeSend` hook so the mid-batch membership and preference tests change the outcome.
- **C9:** the replan names the mechanism that gives `setActiveOrganization` the new session (or sets the active organization through a path proven to work right after sign-up and sign-in) and proves it with E2E in a fresh browser context; account created but accept failed (invalid, revoked or expired between view and accept) has a defined retry through sign-in and is tested.
- **C10:** CONTEXT D-15's deviation is recorded in the ledger with its reason (atomic `ON CONFLICT` insert and `SKIP LOCKED` claim need raw SQL); all notification reads and writes, including the digest claim and stamp, live behind one module with explicit organization and recipient parameters; isolation tests cover insert, claim and stamp across organizations and recipients.
- **C11:** 10-05 depends on 10-03 (or `team-errors.ts` moves to 10-01); the assignee membership check runs inside the assignment transaction under the organization lock, or the plan shows why a deactivation racing an assignment is harmless and tests it; each inbound reply path is listed in the plan with its own test.
- **C12:** `docs/SECURITY.md` states that invitation tokens travel in the URL path, that AIDA ships no access log, and that operators who enable one record tokens; a static test checks that the shipped `Caddyfile` has no `log` directive and that `src` logs no request URL on `/invite`.
