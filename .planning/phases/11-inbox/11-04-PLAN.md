Design note on D-17 for reviewers: a conditional UPDATE alone does not wait for a transaction that is changing the ticket from OPEN to RESOLVED, because the row fails the WHERE condition on the statement snapshot and is skipped without waiting. The reply paths therefore take the ticket row lock first (SELECT … FOR UPDATE on that one row) and then run the conditional UPDATE in the next statement, which reads the committed status. This is a row lock inside one path, not the shared lock protocol D-17 rejected; the auto-close job keeps a pure conditional UPDATE.

| T-11-23 | Tampering | agent public reply committed during the job's close statement | low | accept | The close statement's subquery reads its own snapshot; an agent reply committed in that instant can be followed by a close.
