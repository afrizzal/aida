# Phase 11 — Deferred items (out of scope for the plan that found them)

## Found during 11-07

- **Flaky case in `tests/e2e/bulk-actions.spec.ts`** ("a tag added in bulk is offered by Remove tag, and removing it untags both tickets", line 163). In the combined regression run (`inbox`, `saved-views` and `bulk-actions` specs) it failed once with a Playwright strict-mode violation: `getByRole('option', { name: tag.name, exact: true })` found two options with the same `data-value`. The Add tag picker had not finished its close animation when the Remove tag picker opened, so both popovers listed the tag at the same moment. The bulk bar keeps a single `openPicker` state, so only one picker is logically open at a time. Re-running `bulk-actions.spec.ts` alone passed 6/6. 11-07 does not touch the bulk bar, the selection or this spec. A possible fix: wait for the Add tag listbox to be hidden before clicking Remove tag, or scope the option locator to the open popover. Owner: the phase gate (11-09) or a later fix.
  - **Fixed in b3f8575** (`fix(11-06)`, test only). The test now waits for each closed picker's popover to be hidden, and option and input locators are scoped to `[data-slot="popover-content"][data-state="open"]`. The bulk spec then passed three runs in a row (exit 0 each time, 6/6). All six bulk cases also passed in two combined runs.

## Found during the 11-06 follow-up fix

- **Failing case in `tests/e2e/command-palette.spec.ts`** ("Create ticket from another page goes to the inbox and opens the New Ticket dialog", line 132). It failed in both combined runs (`bulk-actions`, `inbox`, `saved-views`, `command-palette`) and when the spec ran alone (exit 1, 8 passed, 1 failed), although 11-07 recorded 9/9. The server log shows `GET /tickets?new=1` and then `GET /contacts`, and the page ends on Contacts with no "New Ticket" dialog. Something sends the browser back to /contacts after the palette pushes `/tickets?new=1`. The suspect is the `router.replace` in `new-ticket-dialog.tsx` or the palette's close-then-run order in `command-palette.tsx`. Neither was changed in this fix. Owner: 11-07 follow-up or the phase gate (11-09).
  - **Fixed in 9eddbd9** (`fix(11-07)`, product). Neither suspect was the cause. `ContactSearch` (`src/app/(app)/contacts/contact-search.tsx`) called `router.replace("/contacts")` 300 ms after every mount, even with nothing typed. The /contacts page stays mounted until a navigation away commits, so that replace overrode the palette's push to `/tickets?new=1`. A CDP initiator stack traced the `/contacts` RSC request to `ContactSearch.useEffect` (through `setTimeout` and `router.replace`). The search now replaces only when its text differs from the URL's `q`. The spec is unchanged and runs 9/9 three times in a row; the four-spec combined run passed 31/31. See the 11-07 SUMMARY, "Follow-up fix (orchestrator)". Residual: typing in the contacts search and then leaving within 300 ms can still be overridden by the debounced replace.
  - **Residual fixed after the Codex diff critique (D4).** Next.js 16 calls `onRouterTransitionStart` from `src/instrumentation-client.ts` (documented file convention) when a Link click, `router.push`/`replace` or back/forward starts, before the route is fetched. That hook re-broadcasts a window event, and `ContactSearch` clears its pending 300 ms replace when it fires. E2E `contacts.spec.ts` "a navigation started inside the 300 ms debounce is not overridden by the search" holds the destination for 1 s; before the fix the browser ended on `/contacts?q=…`. Commit recorded in `11-REVIEW.md` (Fix status, round 1).
