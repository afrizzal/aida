## Spacing Scale

Declared values (multiples of 4), mapped to Tailwind classes:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px (`gap-1`, `px-1`, `py-1`, `space-y-1`) | Key cap inner padding; help-modal row padding; sidebar group label padding; filter summary row stack; chord hint vertical padding |
| sm | 8px (`gap-2`, `py-2`, `px-2`, `space-y-2`) | Icon + text gaps; strip, bulk bar and auto-close row padding; bulk bar button gap; help-modal section stack; chord hint horizontal padding |
| md | 16px (`p-4`, `px-4`, `pl-4`, `gap-4`, `space-y-4`, `mt-4`, `bottom-4`, `right-4`) | Card and callout padding [P10]; horizontal padding of strip and bulk bar (matches list rows); dialog form stack [DS §6]; space above the sidebar Views section; chord hint offset |
| lg | 24px (`gap-6`, `space-y-6`) | Between the SLA targets form and the auto-close card (existing page `space-y-6`); between help-modal sections |
| xl | 32px (`py-8`) | Vertical padding of the "no views yet" and palette "nothing matches" lines |
| 2xl | 48px | Not used |
| 3xl | 64px | Not used |

Exceptions (each one inherited, none invented here):
- Sidebar view rows use `space-y-0.5` (2px) between rows, copied from the DS §4.1 nav pattern so the Views list matches the nav above it.
- The row checkbox column uses `pt-3` (12px) to line up with the inbox row's pre-existing `py-3`; the row itself keeps its existing `px-4 py-3`, `mt-0.5`, `mt-1.5`, `gap-1.5`.
- shadcn internals (`CommandItem` `px-2 py-1.5`, group heading `py-1.5`, `DialogContent` padding, Button size paddings) stay as shipped; only font sizes are overridden on instances.

Sizes, not spacing: sidebar view rows `h-8`; key caps `h-5 min-w-5`; strip menu trigger and save-view icon button `size-8`; checkbox `size-4` inside an `h-5` alignment box; palette width `sm:max-w-[560px]`; help modal `sm:max-w-[640px]` with body `max-h-[70vh]`; bulk popovers `w-[240px]`; auto-close input `w-24`.

**Every other spacing value used by a new or changed element is on the declared scale (4, 8, 16, 24, 32). No 10px (`gap-2.5`) or 6px (`gap-1.5`) in new elements.**

## Typography

Sizes used by **new** elements in this phase (3 sizes, 2 weights):

| Role | Size | Weight | Line height | Where |
|------|------|--------|-------------|-------|
| Caption | 12px (`text-[12px]`) | 400 (600 for the sidebar "Views" heading) | 1.5 | Sidebar group labels, help text under fields, palette group headings and shortcut hints, key caps, palette footer, "Private"/"Shared" badges, chord hint, bulk-cap note |
| Body / label | 13px (`text-[13px]`) | 400 / 600 | 1.5 | Sidebar view rows, strip view name (600), bulk bar count (600), bulk and strip buttons, palette items, dialog descriptions, filter summary, callouts, help-modal rows, auto-close copy |
| Title / input | 15px (`text-[15px]`) | 600 for titles, 400 for the palette input | 1.2 | `DialogTitle` of every new dialog (`text-[15px] font-semibold tracking-tight`) and the auto-close `<h2>`; the palette search input is 15px/400 so it reads as the focus of the dialog. Help-modal section headings are 13px/600 (body row) |

- 18px stays only where it already is (the SLA page `<h1>`, the TopBar `<h1>`, EmptyState heading); no new 18px text.
- 14px stays only where it already is (sidebar nav items, ticket subject in list rows, EmptyState body); no new 14px text.
- Weights: 400 and 600 for new text. The one 500 (`font-medium`) is the active sidebar view row, which reuses the DS §4.1 active-nav class string verbatim (`bg-sidebar-accent font-medium text-sidebar-accent-foreground`) so a selected view looks exactly like a selected nav item. Existing 500 on filter chips and list rows is untouched.
- Explicit `text-[Npx]` only; never `text-xs` / `text-sm` / `text-base` [DS §3, §8 rule 6]. shadcn internals that ship named sizes are overridden on the instance: `CommandItem` and `CommandEmpty` → `text-[13px]`, `CommandGroup` heading → `**:[[cmdk-group-heading]]:text-[12px]`, `CommandShortcut` → `text-[12px]`, `CommandInput` → `text-[15px]`, `DialogTitle` → `text-[15px] font-semibold tracking-tight`, `DialogDescription` → `text-[13px]`, `Button size="sm"` → `text-[13px]`.
- Caption vs body are separated by colour as well as size [P10]: 12px is always `text-muted-foreground` (or `text-sidebar-foreground/70` in the sidebar); the exceptions are the key caps (`text-foreground` on `bg-muted`) and the badges.
- Key cap: `<kbd className="inline-flex h-5 min-w-5 items-center justify-center rounded border border-border bg-muted px-1 font-mono text-[12px] text-foreground">`. Letters are shown lowercase exactly as typed (`g`, `t`, `?`); the modifier shows `⌘` on Apple platforms and `Ctrl` elsewhere, decided on the client when the dialog opens [RL].

## Surface 1 — Sidebar "Views" section (AIDA-47, D-06)

Placement: inside `Sidebar`, below the five nav links and above the user footer. The `<nav>` becomes `flex-1 overflow-y-auto px-2 py-2` so a long view list scrolls inside the nav and the user footer stays pinned [RL]. The nav links keep their existing markup and classes.

Structure (`<section aria-labelledby="sidebar-views-heading" className="mt-4">`):
- Heading `<h2 id="sidebar-views-heading" className="px-3 py-1 text-[12px] font-semibold text-sidebar-foreground/70">Views</h2>`.
- Two groups, in this order [RL]: **Private** (the viewer's own private views) and **Shared** (the organization's shared views, whoever owns them). Each group has a label `<p className="px-3 py-1 text-[12px] text-sidebar-foreground/70">` and a `<ul className="space-y-0.5">`. A group with no views is not rendered.
- Row: `Link` `flex h-8 items-center gap-2 rounded-md px-3 text-[13px] transition-colors` + icon `ListFilter size-4 shrink-0` + `<span className="min-w-0 truncate">{name}</span>`.
  - Inactive: `text-sidebar-foreground/70 hover:bg-sidebar-accent/60 hover:text-sidebar-foreground`, icon `text-sidebar-foreground/60 group-hover:text-sidebar-foreground` [DS §4.1].
  - Active (the URL's `sv` equals this view's id): `bg-sidebar-accent font-medium text-sidebar-accent-foreground`, icon `text-sidebar-accent-foreground`, `aria-current="page"` [DS §4.1]. The "Tickets" nav link stays active too (it is the parent section).
  - The row carries `title={name}` so a truncated name can be read on hover; the strip shows the full name (Surface 2).
- Order inside each group: `position`, then name, then id, as returned by the server [CTX D-04]. No drag reordering [CTX D-04, Deferred].
- No views at all: under the heading, one line `<p className="px-3 py-1 text-[12px] text-sidebar-foreground/70">` with the Copywriting "Views empty" text. This is a section hint inside the sidebar, not a page empty state, so the DS §4.3 halo pattern does not apply (same reasoning as Phase 10's "No pending invitations." line) [RL].
- Rows carry no inline actions; editing and deleting happen from the strip (Surface 2) [RL].

Data: the `(app)` layout loads the list (id, name, visibility, href) server-side through the membership-checked saved-view read (D-01) and passes it to `Sidebar`; a member never receives another member's private view [CTX D-12]. The sidebar refreshes after save, edit and delete (`revalidatePath` on the `(app)` layout).

Link target [RL]: each row's `href` is `/tickets?sv={id}&{stored filters as the usual URL params}` (built on the server from the validated stored filters; `limit` never included). Because the full filter set is in the URL, the existing `FilterChipRow` shows the view's filters as active chips without any change to how it reads the URL.

## Surface 2 — Saved views in the inbox (AIDA-47, D-03, D-04, D-05)

### 2a. "Save view" button (filter row)

In `FilterChipRow`'s second row (Status / Tag / Custom field), at the right: `<Button variant="ghost" size="icon" className="ml-auto size-8">` with `BookmarkPlus size-4`, `aria-label="Save these filters as a view"`, Tooltip "Save view" [RL: icon-only because the 328px row already holds three buttons].
- Disabled when no filter is set (Tickets = All, no status, no tag, no custom field, no search); the Tooltip then reads the Copywriting "Save disabled reason".
- Opens the Save view dialog (2c) in **create** mode.

### 2b. Saved-view strip

Rendered by `TicketListPanel` between `FilterChipRow` and the first row, only when the URL has `sv` [RL]:
- Container `flex items-center gap-2 border-b border-border/70 px-4 py-2`.
- `ListFilter size-4 text-muted-foreground` + name `min-w-0 flex-1 truncate text-[13px] font-semibold text-foreground` (full name in `title`) + `Badge variant="secondary" className="text-[12px]"` "Private" or "Shared".
- Menu (only when the viewer may edit this view per D-04): ghost `Button size="icon" className="size-8"` `Ellipsis size-4`, `aria-label="View options"` → `DropdownMenu` items "Edit view" (`Pencil`) and "Delete view" (`Trash2`, `text-destructive`). A viewer who may not edit sees no menu.

Strip states (the server decides by comparing the URL filters with the stored filters, `limit` excluded):

| State | Render |
|-------|--------|
| Applied (URL filters equal the stored filters) | As above |
| Changed (the agent changed a chip after opening the view) | A second line under the name row, `flex flex-wrap items-center gap-2 px-4 pb-2`: 12px muted "Filters changed"; `Button variant="outline" size="sm"` "Save changes" (only when the viewer may edit; opens 2c in **edit** mode with the on-screen filters); `Button variant="ghost" size="sm"` "Reset" (navigates to the view's stored href). The sidebar row stays active; `sv` stays in the URL |
| Broken reference (stored `tagId` or `cf.definitionId` no longer exists in the organization) [CTX D-05] | Under the strip, `mx-4 my-2` warning callout, `role="status"`: the Copywriting "Broken reference" sentence naming what is missing (tag, custom field, or both), then either the "Edit view" button (`Button variant="outline" size="sm"`, opens 2c in edit mode) or, for a viewer who may not edit, the Copywriting "Broken reference, cannot edit" line. The filter is **not** dropped: the list runs with the stored filters, so it usually shows the existing "no tickets match this view" line below the notice |
| Not available (`sv` unknown, deleted, or a private view of someone else) | No strip. A 13px muted line `px-4 py-2 border-b border-border/70` with the Copywriting "View not available" text and a ghost `sm` "Clear" button that removes `sv` from the URL. The list uses the URL filters as plain filters. The response is identical for "deleted" and "someone else's private view", so nothing about other members' views is revealed |

*Amended 2026-11-08 after the Codex diff critique round 2, E1 (run-loop K31):* when the viewer's member row is gone, the list panel shows only the "View error: membership ended" line (with its "Clear" button): no filter row, so no search, no "Save view" and no "New Ticket" button, and no rows. The ticket page (`/tickets/[id]`) then shows the same panel and, in the reading pane, the existing `EmptyState` (`ShieldOff` icon) with the same copy split in two: heading "Your access to this workspace has ended." and body "Sign out, then sign in again." No ticket data is loaded and no error boundary is reached. If the new-ticket dialog is already open, a refused create keeps it open and shows the same copy as a 13px `text-destructive` line above the footer, `role="alert"`.

### 2c. Save view / Edit view dialog

`DialogContent` (default width), body `space-y-4`:
- Title: create "Save view"; edit "Edit view". Description (13px muted): Copywriting row "Save dialog description" / "Edit dialog description".
- **Name** `Input` (required, trimmed, 1 to 80 characters, `maxLength={80}`), autofocused; edit mode pre-fills the stored name [CTX D-03].
- **Who can see it** `Select` (`h-8 text-[13px]`), options "Only me" (`PRIVATE`, default in create mode) and "Everyone in this workspace" (`SHARED`). Help text (12px muted, `aria-describedby`): Copywriting "Visibility help". In edit mode the Select is shown only to the view's owner; an admin or owner editing someone else's shared view sees a 12px muted line "Shared with everyone in this workspace." instead (only the owner changes visibility) [RL].
- **Filters** summary: label 13px/600 "Filters", then `<dl className="space-y-1 rounded-lg border border-border/70 p-4 text-[13px]">`, one row per set filter (`<dt className="text-muted-foreground">` / `<dd className="text-foreground">`, side by side `grid grid-cols-[120px_1fr] gap-x-2`): "Tickets" (always), "Status" (always; "Any status" when none), "Tag", "Custom field", "Search" (rows omitted when not set). Values follow the Copywriting "Filter summary" rows. Values are escaped text.
  - In edit mode from "Save changes", a 12px muted line under the summary: Copywriting "Replacing filters note".
  - A broken filter row shows its value as Copywriting "Missing reference value" in `text-destructive` and a ghost `Button size="icon" className="size-8"` `X` `aria-label="Remove the {Tag|Custom field} filter"`; removing it drops that filter from the draft only. Saving while a broken row remains is refused by the server and shows the matching error [CTX D-05].
- **Shared-search warning** [CTX D-05]: whenever "Who can see it" is "Everyone in this workspace" **and** the filters include search text, the warning callout (Color → Warning) appears directly above the footer with the Copywriting "Shared search warning", `role="status"`. It updates live as the Select changes.
- **Visibility narrowing note**: when the owner switches a stored shared view to "Only me", a 12px muted line under the Select: Copywriting "Make private note".
- Footer: "Close without saving" (outline) and the primary button ("Save view" in create mode, "Save changes" in edit mode). Pending: `Loader2 className="mr-2 size-4 animate-spin"` + "Saving…", fields disabled.
- Outcomes:
  - **Success (create):** dialog closes, navigate to the new view's href (so the strip and the active sidebar row show it), `toast.success("View saved.")`.
  - **Success (edit):** dialog closes, navigate to the view's (new) href, `toast.success("View updated.")`.
  - **Failure:** dialog stays open; exactly one Copywriting "View error: …" row as a destructive callout above the footer, `role="alert"`; fields keep their values.

### 2d. Delete view confirmation

`Dialog`: title, description and buttons per Copywriting "Destructive confirmation: Delete view" (description differs for private and shared). "Keep view" (outline) and "Delete view" (destructive). Pending: spinner + "Deleting…". Success: dialog closes, navigate to `/tickets` with the same filter params minus `sv`, `toast.success("View deleted.")`. Failure: dialog stays open, error as a 13px `text-destructive` line above the footer, `role="alert"`.

Keyboard and focus (2a to 2d): dialogs trap focus and return it to their trigger (radix default); after a delete, focus moves to the list panel's first focusable element; the strip menu is a radix menu (arrow keys, Escape). The global dispatcher is inactive while any of these is open [CTX D-13].

## Surface 3 — Row selection and the bulk action bar (AIDA-48, D-10)

### 3a. Row checkbox

`TicketListRow` changes from one `<Link>` to a row container with two siblings, so the checkbox is never inside the link [RL, required: interactive content inside `<a>` is invalid]:
- Container `<div className="group/row relative flex shrink-0 border-b border-border/70 has-[>a:focus-visible]:ring-2 has-[>a:focus-visible]:ring-inset has-[>a:focus-visible]:ring-ring">` carrying the existing state classes: open ticket `border-l-2 border-l-primary bg-accent` (unchanged); checked and not open `bg-muted`; otherwise `hover:bg-muted/50`.
- Checkbox column `<div className="flex shrink-0 items-start pl-4 pt-3"><div className="flex h-5 items-center"><Checkbox …/></div></div>`; `aria-label="Select ticket #{number}: {subject}"`. Always visible (not hover-only), so touch and keyboard users can find it [RL].
- Link `className="block min-h-[80px] min-w-0 flex-1 py-3 pr-4 pl-2 outline-none"` holding the existing three lines unchanged (`pl-2` = 8px between checkbox and text).
- `TicketListSkeleton` rows gain a `Skeleton className="size-4"` in the same column so the layout does not shift on load.
- At 100 selected, every unchecked checkbox is `disabled` and the bar shows the cap note; `x` on an unchecked row does nothing [CTX D-08: at most 100 ids].

Selection rules [CTX D-10]:
- Only explicitly checked rows (click or `x`). No "select all" control of any kind in this phase [RL; "select all matching" is Deferred].
- Selection lives in a client provider in `tickets/layout.tsx`; it survives opening tickets (`/tickets` ↔ `/tickets/[id]`) and "Load more", and clears when any filter or `sv` changes, or when the user leaves `/tickets`.

### 5b. Row cursor (j / k) [RL]

- `j` / `k` move real DOM focus to the next / previous row's link (`focus()`, then `scrollIntoView({ block: "nearest" })`), so screen readers announce the row and `Enter` opens it through the browser's own link activation (the dispatcher adds nothing when the link has focus).
- With no cursor yet, `j` and `k` both start at the open ticket's row when it is in the list, otherwise at the first row. No wrap at either end.
- Cursor style: the row container's `has-[>a:focus-visible]:ring-2 ring-inset ring-ring` (Surface 3a). It must stay visible on the open-ticket row (`bg-accent`) and on checked rows (`bg-muted`).
- `x` toggles the checkbox of the row that holds the cursor; the checkbox state and the bar's live count are the feedback.
- `j` / `k` past the last loaded row do nothing; they never trigger "Load more".

### 5c. Ticket-page keys [RL]

- `a` and `s` open the existing assignee and status dropdowns in `TicketMetaHeader` (made controlled) with focus on the current value; `t` opens the existing "Add tag" popover with focus in its search input.
- `r` and `n` switch `ComposerToggle` to Public Reply / Internal Note exactly as a click would, then focus the textarea with the caret at the end. Existing text is kept.

### 5d. Chord hint [RL]

### Addendum accessibility and 360px

- **Labels:** every control has a visible `<Label htmlFor>`; the Switch's accessible name is the switch label, its description the help plus any shown warning ids (so a screen-reader user learns why it is disabled).
- **`aria-describedby`:** subject → `auto-close-notice-subject-help auto-close-notice-subject-count` plus the `FormMessage` id while an error shows; body likewise with its own ids; `aria-invalid="true"` only while an error shows. The scope block (`auto-close-notice-scope`) is added to the Switch's describedby so the recipient rule is read before turning it on [RL].
- **Focus order** (DOM order, no `tabIndex` > 0): email-settings link (if shown) → Switch → Subject → Message → Save. Placeholders, preview and scope lines are static text. On a failed client submit focus moves to the first invalid field; after a server refusal focus stays on Save and the `role="alert"` callout is announced; after success focus stays on Save.
- **Live region for the save result:** the status line (`role="status"`, polite) re-renders from the stored values after each save, so the new state is announced even if the toast is missed; the toast is supplementary. Counters are not live (they are read through describedby on focus).
- **Feed row:** the `<summary>` is a native disclosure (expanded state announced by the browser); icons are `aria-hidden`; meaning is in the text.
- **Contrast:** callout text uses the parent Warning and Destructive patterns unchanged; the email-settings link inside the warning is `text-foreground underline`; `text-destructive` on the failed-row icon only.
- **360px:** the card is full width inside the page's existing padding; the switch row keeps the Switch at the right with the label wrapping (`min-w-0` on the text column); help and counter lines wrap (`flex-wrap`); `Input` and `Textarea` are `w-full`; the preview and the `<details>` box use `break-words` and `whitespace-pre-wrap`, so a 150-character subject, a 2,000-character message with no spaces and a long workspace name never cause horizontal scroll; the Save button keeps its natural width. Feed rows wrap centred; the disclosure box is `max-w-full`.
