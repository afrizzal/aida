## Typography

Sizes used by **new** elements in this phase (3 sizes, 2 weights), identical to Phase 11:

| Role | Size | Weight | Line height | Where |
|------|------|--------|-------------|-------|
| Caption | 12px (`text-[12px]`) | 400 (600 for the "Linked tickets" label) | 1.5 | Relation chips, snoozed chip, feed event rows, "Moved from #N" marker, picker reasons and ticket numbers, popover help text and preset times, field help, time-zone line |
| Body / label | 13px (`text-[13px]`) | 400 / 600 | 1.5 | Menu items, picker rows, dialog descriptions and lists, confirmation ticket rows (number 600), banner, callouts, preset labels, field labels, merged composer line, public notice |
| Title | 15px (`text-[15px]`) | 600 | 1.2 | `DialogTitle` of both dialogs (`text-[15px] font-semibold tracking-tight`); the snooze popover heading |

- 18px stays only where it already is (ticket subject `<h1>`, public page `<h1>`, EmptyState heading); 14px stays only where it already is (message bodies, public CSAT heading). No new 18px or 14px text.
- Weights: 400 and 600 for new text. Existing 500 (`font-medium`) in `ThreadMessage` headers and filter chips is untouched.
- Explicit `text-[Npx]` only; never `text-xs` / `text-sm` / `text-base` [DS §3, §8 rule 6]. Overrides on shadcn internals as in Phase 11: `CommandItem`, `CommandEmpty` → `text-[13px]`; `CommandInput` → `text-[13px]` inside dialogs [RL: the picker is a field in a form, not the palette's focus]; `DialogTitle` → `text-[15px] font-semibold tracking-tight`; `DialogDescription` → `text-[13px]`; `DropdownMenuItem` → `text-[13px]`; `SelectTrigger`, `SelectItem` → `text-[13px]`; `Button size="sm"` → `text-[13px]`; `Input` in the popover → `text-[13px]`.
- Ticket numbers use `tabular-nums` wherever they line up in a list (picker rows, relation chips).
- Caption vs body are separated by colour as well as size [P11]: 12px is `text-muted-foreground`, except the ticket reference inside a chip or event row, which is `text-foreground` so the link stands out.

## Surface 2 — Relations (AIDA-52, D-03 to D-06)

### 2a. Linked tickets row

Rendered by `TicketMetaHeader` directly under its second row, only when the ticket has at least one relation [RL]:
- Container `<section aria-labelledby="linked-tickets-heading" className="flex flex-wrap items-center gap-2 border-b border-border/70 px-6 py-2">`.
- Label `<h2 id="linked-tickets-heading" className="text-[12px] font-semibold text-muted-foreground">Linked tickets</h2>`.
- One chip per relation, as an `<li>` in a `<ul className="contents">`:
  - Chip `inline-flex h-6 max-w-full items-center gap-1 rounded-md border border-border/70 bg-muted px-2 text-[12px]`.
  - Label (12px muted) from this ticket's side, per D-04 and the Copywriting "Relation labels" row: "Duplicate of", "Has duplicate", "Child of", "Parent of", "Related to".
  - Link `<Link href="/tickets/{id}" className="inline-flex min-w-0 items-center gap-1 text-foreground hover:text-primary-emphasis hover:underline">` with `#{number}` (`tabular-nums`) and the subject `<span className="max-w-[200px] truncate">`; the full subject is in `title` and in a Tooltip.
  - Remove: ghost `Button size="icon" className="size-5"` `X size-3`, `aria-label` = Copywriting "Remove link (aria-label)". Applies at once, without a confirmation, because a link is restored by linking again and both sides are audited [RL, as P11 bulk actions]. Pending: the chip shows `Loader2 size-3 animate-spin` in place of the X and is `aria-busy="true"`.
  - **Merge link** (the `DUPLICATE_OF` created by a merge, D-06): no remove button; in its place `LockKeyhole size-3 text-muted-foreground` with `aria-label` and Tooltip = Copywriting "Merge link locked". The server refuses its removal anyway [CTX D-06].
- Order [RL]: Parent of, Child of, Duplicate of, Has duplicate, Related to; inside each label by ticket number ascending.
- Overflow [RL]: at most 8 chips are shown; when there are more, a ghost `Button size="sm" className="h-6 px-2 text-[12px]"` "Show all {N}" expands the row in place and becomes "Show fewer". The expanded state is not stored.
- The other ticket's reference is resolved through `scopedDb` after the membership check [CTX D-01, D-18]; a relation whose other ticket is no longer readable is not rendered [RL].
- Remove outcome: success → `toast.success` Copywriting "Link removed"; the row refreshes (the other ticket's page shows the change on its next load). Failure → the chip stays, and one destructive line `text-[12px] text-destructive` with `role="alert"` appears at the end of the row with the matching "Link error" row; it clears on the next action.

### 2b. Link a ticket dialog

`Dialog`, `DialogContent className="sm:max-w-[560px]"`, body `space-y-4`:
- Title "Link a ticket"; description (13px muted) Copywriting "Link dialog description".
- **Link type** `Select` (`h-8 text-[13px]`, label "This ticket"), five options from this ticket's side [RL; covers both directions of the two directional types]: "is a duplicate of" (`DUPLICATE_OF`, this → other), "has a duplicate" (`DUPLICATE_OF`, other → this), "is related to" (`RELATED_TO`), "is a child of" (`CHILD_OF`, this → other), "is the parent of" (`CHILD_OF`, other → this). Default "is related to" [RL: the only type with no direction, so the safest default].
- **Ticket** picker (Surface 2c), label "Ticket".
- Footer: "Close" (outline) and "Link tickets" (default), disabled until a ticket is chosen. Pending: `Loader2 className="mr-2 size-4 animate-spin"` + "Linking…", fields disabled.
- Success: dialog closes; the Linked tickets row appears or gains the chip; `toast.success` Copywriting "Link added".
- Failure: dialog stays open with its values; exactly one Copywriting "Link error: …" row as a destructive callout above the footer, `role="alert"`. A call that rejects (no returned code) shows "Link outcome unknown" instead [P11 D2].

### 2c. Ticket picker (shared by 2b and 3a)

`Command` with `shouldFilter={false}` (results are ranked by the server):
- `CommandInput` (13px), placeholder Copywriting "Picker placeholder", autofocused.
- Search starts at 1 character when the text is `#` followed by digits or digits only (number lookup), otherwise at 2 characters; debounce 300 ms; stale responses are discarded [P11 4d; RL].
- Endpoint: checks membership first [CTX D-01], searches the actor's organization only, excludes the current ticket, returns at most 10 rows with id, number, subject, status, and the eligibility flags the dialog needs (already linked; for merge: same contact and already merged). No message text, no contact name or email is returned [RL].
- Row (`CommandItem`, `flex items-center gap-2 text-[13px]`): `#{number}` (`w-12 shrink-0 text-[12px] text-muted-foreground tabular-nums`), subject (`min-w-0 flex-1 truncate`), `StatusChip` at the right. The chosen row shows `Check size-4` before the number and stays highlighted; choosing another row replaces it.
- Ineligible rows stay visible but `disabled`, with the reason as a 12px muted line under the subject (Copywriting "Picker reason: …"). In the link dialog only "Already linked" applies; in the merge dialog the two merge reasons apply ("Different customer" and "Already merged into another ticket"); a target that has received merges is eligible. The server still enforces every rule [CTX D-07].

| State | Render |
|-------|--------|
| Query under the minimum | One non-selectable 13px muted line, `py-8 text-center`: Copywriting "Picker start" |
| Waiting for the first response | One non-selectable row: `Loader2 size-4 animate-spin` + 13px muted "Searching tickets…" |
| No results | `CommandEmpty` `py-8 text-[13px] text-muted-foreground`: Copywriting "Picker no results" |
| Request failed or refused | One non-selectable 13px muted row: Copywriting "Picker error"; membership ended shows the membership row instead |
| Results | Up to 10 rows; the list scrolls inside the shipped `max-h-72` |

## Surface 3 — Merge (AIDA-53, D-07 to D-09)

### 3a. Merge dialog

One `Dialog` (`sm:max-w-[560px]`) with two steps; the title and footer change per step, focus moves to the step's first element on each change [RL].

**Step 1 — pick the target**
- Title "Merge this ticket into another"; description (13px muted) Copywriting "Merge pick description" naming the current ticket.
- The ticket picker (2c) with the merge reasons.
- Footer: "Close" (outline) and "Review merge" (default), disabled until an eligible ticket is chosen.

**Step 2 — confirm** (the confirmation required by AIDA-53; the dialog is a convenience, the server enforces every rule [CTX D-07])
- Title Copywriting "Merge confirm title" (`Merge #{source} into #{target}?`).
- Ticket pair, `rounded-lg border border-border/70 p-4 space-y-2`: two rows `grid grid-cols-[48px_1fr_auto] items-center gap-2 text-[13px]`: 12px muted "From" / "Into", `#{number}` (600, `tabular-nums`) + subject (truncate, full in `title`), `StatusChip`.
- What happens, `<ul className="list-disc space-y-1 pl-4 text-[13px] text-foreground">`: the four Copywriting "Merge consequences" rows. When the pair already has a link, a fifth row, Copywriting "Merge replaces link" [RL, see Assumption 6].
- Warning callout (Color → Warning): Copywriting "Merge cannot be undone".
- Footer: "Back" (outline, returns to step 1 with the choice kept), "Keep tickets separate" (outline, closes), "Merge tickets" (destructive). Pending: spinner + "Merging…", all buttons disabled, `Esc` and outside click do not close the dialog while pending [RL].
- **Success:** dialog closes; navigate to `/tickets/{target}`; `toast.success` Copywriting "Merge done". The list panel keeps its filters.
- **Refusal (returned code, whole merge rolled back, D-08):** the dialog stays on step 2; a destructive callout above the footer, `role="alert"`, starts with "Nothing was changed." then the matching "Merge error: …" row. "Merge tickets" stays enabled only for the "unknown" refusal; for every rule refusal it is disabled and "Back" takes focus [RL].
- **Rejected call (no returned code):** the callout reads Copywriting "Merge outcome unknown"; "Merge tickets" is disabled; the only way on is "Close" and a page refresh [P11 D2, E3].

## Surface 4 — Snooze (AIDA-54, D-12 to D-17)

### 4a. Time zone rule (all snooze times)

- Times are stored in UTC and shown and chosen in the viewer's browser time zone [CTX D-12].
- `LocalDateTime` (client) renders `<time dateTime="{ISO}">`. The server render and the first client render show the UTC form (`Tue, Nov 10, 02:00 UTC`) so hydration matches; after mount it switches to the local form with the same formatter in the browser zone: `Intl.DateTimeFormat("en-US", { weekday: "short", month: "short", day: "numeric", hour: "2-digit", minute: "2-digit", hourCycle: "h23", timeZone })` → `Tue, Nov 10, 09:00`. Its `title` holds the full form with the zone name (`timeZoneName: "short"`) [RL].
- The popover always shows the zone in words: Copywriting "Time zone line" with the IANA name from `Intl.DateTimeFormat().resolvedOptions().timeZone` [CTX D-12: "the control and its display say which time zone is meant"].

### 4b. Snooze trigger (top bar)

- Not snoozed: ghost `Button size="sm" className="gap-2 text-[13px]"` `AlarmClock size-4` "Snooze".

## Assumptions (Claude's discretion, recorded for the planner) [RL]

1. **Placement:** snooze control and "More ticket actions" menu at the end of the top bar's right cluster; the Linked tickets row under the header's second row, rendered only with at least one relation.
2. **Link types offered:** five directional options from the current ticket's side; default "is related to".
3. **Picker:** shared by both dialogs; number lookup from 1 digit, text from 2 characters, 300 ms debounce, 10 results, no contact data returned; ineligible rows shown disabled with a reason.
4. **Relation chips:** at most 8 shown, then "Show all"; order by label group then number; a relation whose other ticket is not readable is not rendered.
5. **Removing a link needs no confirmation;** the merge link has no remove button.
6. **Existing link at merge time** (CONTEXT discretion): recommended to **replace** it with `DUPLICATE_OF` inside the merge transaction, with `RELATION_REMOVED` and `RELATION_ADDED` audit rows, and the "Merge replaces link" line on the confirmation. Remove that link first, then merge.") is added; the choice is recorded in the plan and tested.
7. **Composer on a merged source is replaced** by a line pointing to the target, because a new message on the source would be visible on neither status link under D-09. Recommended: the reply and note actions also refuse a merged source on the server; the planner decides and records it.
8. **Snoozable tickets:** `NEW`, `OPEN`, `PENDING`, `RESOLVED`, not merged (`RESOLVED` must be snoozable for the D-17 auto-close test). `CLOSED` and merged sources are refused. Bounds: at least 5 minutes ahead, at most 365 days. Wake is always allowed while snoozed.

10. **Snoozed filter:** URL `snoozed=1`; a toggle in the filter row's second row, which becomes `flex-wrap`; no new keyboard key or palette command.
11. **Feed:** oldest first; messages before events on a tie; no paging; centered 12px event rows matching the existing system-event style; bulk rows marked "(bulk change)".
12. **Public merged source:** a neutral "Combined" label replaces the status chip and a notice explains that the conversation continues; nothing about the target is shown. The target's page shows nothing about the merge.
13. **Merge success navigates to the target.**
