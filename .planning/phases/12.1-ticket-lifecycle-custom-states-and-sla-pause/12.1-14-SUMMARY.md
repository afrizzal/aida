## What changed

- **List row (UI-SPEC 4e, Surface 5):** the row now takes a `defaultStateId` prop. The subject is `font-medium` when `ticket.stateId === defaultStateId`, and that test replaces the old `NEW` check. The row renders `StateChip` from `ticket.state`, and `SlaDueChip` receives `pausedAt={ticket.slaPausedAt}`. `slaPausedAt` is a scalar on Ticket, so the list query's include already selects it, and `list-query.ts` was not touched.
- **Bulk bar (UI-SPEC 3b):** `StateOptions` follows the `TagOptions` pattern. It uses `Command filter={matchLabel}` and shows the "Find a status…" input when there are more than `SEARCH_THRESHOLD` (8) states. `CommandEmpty` uses `bulkPickerNoMatch`. There is one `CommandGroup` per non-empty group, in `STATE_GROUP_KEYS` order, with the `GROUP_LABELS` heading and the 12px `GROUP_CLASS` taken from `command-palette.tsx`. Each item is `text-[13px]`, with `value` set to the state id, `keywords` set to `[name]`, a `StateDot` and the name in `OptionLabel` (full name in `title`). The button label, icon, pending lock, refocus rules and outcome callouts are unchanged. The internal picker key stays `status`. `STATE_NOT_FOUND` maps to "That status no longer exists. Pick another status." after "Nothing was changed.". `MERGED_SOURCE` and the unknown-outcome path are unchanged.
- **Service (D-09, T-12.1-50, T-12.1-51):** `findMissingReferences` runs one `ticketState.findMany` with `id in`, `organizationId` and `deletedAt: null`. `missing.state` is true when fewer distinct ids come back than were asked for, which covers deleted, unknown, foreign and sentinel ids. `requireReferences` refuses on `missing.state`. The missing type is `{ state, tag, customField }` in the service, in `SavedViewPanel`, in the strip and in the dialog.
- **Strip (4d):** the local sentence function is replaced by `stripMissingSentence(missing)` followed by " Edit the view to remove it.". The strip takes a `states` prop and passes it to the edit dialog. The Edit view path, styles and focus are unchanged.
- **Dialog (4d):** the dialog takes a `states` prop (in group, then sort order, from the loader). The Status row shows the names of the existing states joined with ", ", or "Any status" when the filter has no state ids. When there are missing ids, the `BrokenValue` follows the names, with the aria-label "Remove the deleted statuses from the Status filter", and its remove button removes only the missing ids. The missing-reference error row now reads the UI-SPEC text through `SAVED_VIEW_ERROR_MISSING_REFERENCE`. `STATUS_LABELS` and the `TICKET_STATUSES` import are removed. Missing ids are sent on save unchanged, so the server refuses them.
- **BrokenValue focus change for tags and custom fields (recorded as the plan asks):** removing a missing tag or custom field used to drop focus to `<body>` when the button unmounted. Now `removeTag`, `removeCustomField` and `removeMissingStates` all call `submitRef.current?.focus()`, which focuses the primary button ("Save view" / "Save changes"). The copy is unchanged.
