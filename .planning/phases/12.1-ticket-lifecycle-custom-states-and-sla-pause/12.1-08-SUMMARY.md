## Frozen contract for plan 12.1-12

Error codes (`StateAdminErrorCode`): INVALID, INVALID_NAME, DUPLICATE_NAME, INVALID_COLOR, STATE_NOT_FOUND, NOT_ALLOWED, MEMBERSHIP_ENDED, NOT_OPEN_GROUP, LAST_IN_GROUP, REPLACEMENT_REQUIRED, REPLACEMENT_INVALID. Role keys (`StateRoleKey`): new, reopen, resolve, autoClose, mergeClose.

Every write takes `(client, actor: { userId, orgId }, raw: unknown, hooks?)` and returns `{ ok: false, error }` on refusal:

- `createTicketState(raw: { group, name, colorToken })` -> `{ ok: true, state: { id, name, colorToken, group, sortOrder } }`
- `updateTicketState(raw: { stateId, name?, colorToken? })` (at least one; no group field) -> `{ ok: true, state }`
- `moveTicketState(raw: { stateId, direction: 'up' | 'down' })` -> `{ ok: true, position (1-based), total, group, name }`
- `setDefaultTicketState(raw: { stateId })` -> `{ ok: true, defaultStateId, name }`
- `deleteTicketState(raw: { stateId, replacementStateId: string | null })` -> `{ ok: true, movedCount, rolesMoved, name, replacementName (null without replacement) }`
- `listStatesForSettings(client, actor)` -> `{ ok: false, error: 'membership_ended' }` or `{ ok: true, states: [{ id, name, colorToken, group, sortOrder, ticketCount, roles }], defaultStateId, isAdmin }`

Hooks (test seams): onTransactionStart, afterConfigLock, afterStateLock, afterTicketsLocked, beforeCommit, clock.

## Race list (tests/integration/ticket-state-delete-race.test.ts)

1. Deletion holds the state lock (afterStateLock); a state change to it waits on its FOR SHARE, then STATE_NOT_FOUND; the ticket is unchanged.
2. A state change holds the target's share lock and the ticket (afterItem); the deletion waits on the state lock, then moves that ticket too (agent row, then the deletion's row with batchId).
3a. A priority change holds the ticket row; the deletion waits on the ticket lock, moves it, the new priority is kept.
3b. A move out of the deleted state holds the ticket row; the deletion waits, reads the committed state and skips it (movedCount 0).
4. A customer reply holds the config share lock (afterResolve); deleting the reopen state waits on the config row, then moves the reopened ticket and re-points reopenStateId.
5. Two admins delete the same state; the second waits on the config row behind the first and gets STATE_NOT_FOUND.

Every wait is `waitForBlockedBy` on recorded backend PIDs; no timed wait (`grep -cE 'setTimeout|sleep'` prints 0); every pair settles through `Promise.allSettled` with an explicit no-40P01 assertion.

## Deviations from Plan

None in behaviour. Notes:
- `moveTicketState` locks the whole active group FOR UPDATE (ascending id) instead of only target and neighbour, since renumbering 0..n-1 may write any row of the group; still the D-15 order (config, then states in ascending id).
- The removed-member fixture is a former admin (member row deleted), so the gate tests show that even an ex-admin is refused with MEMBERSHIP_ENDED.
