## Create races (review C7)

All five pass in `tests/integration/create-ticket-state-race.test.ts`; each binds its waits to backend PIDs recorded at run time (`backendPid` inside the create transaction through the observer seam, `pg_backend_pid()` on the admin pg client) and `waitForBlockedBy` on the global client; no timers. PID values change every run and are not persisted.
- C7-1 (delete the default first): create blocked by the admin PID, ticket created in Triage.
- C7-2 (create first, then delete): admin config lock blocked by the create PID; ticket created in New, then moved to Triage; no ticket left in New.
- C7-3 (change the default first): create blocked; ticket created in Triage.
- C7-4 (create first, then change): ticket stays in New; config points at Triage.
- C7-5 (state-only holder soft-deletes New): create blocked, then rejects with DefaultStateUnavailableError; no ticket, contact or counter left.
- No side rejected with 40P01.

## T-12.1-06 acceptance

ON DELETE RESTRICT refuses a hard delete of a state that a ticket or a role uses (proven in the schema test). Accepted as planned: states are only soft-deleted (K42), and no code deletes an organization (checked at planning time), so the restriction never blocks a product path.

**2. [Rule 3 - Blocking] Observer seam type**
- Found during: Task 2 compile check (TS2345 in create-ticket.ts)
- Issue: the scopedDb transaction client is not assignable to `Prisma.TransactionClient`.
- Fix: the seam's hooks take `StateQueryClient` (structural `$queryRaw` client) from ticket-states.ts.
- Files: src/lib/tickets/create-ticket.ts. Commit: dabff2e (the Task 1 commit had the first form, which the Task 1 verify does not type-check)

**3. [Test correction] scopedDb config isolation case**
- Found during: Task 3. scopedDb overrides a caller-supplied `organizationId` in `where` with its own, so `findFirst({ where: { organizationId: orgA } })` on scopedDb(orgB) returns B's row, never A's. The case now selects A's row by A's role id (null), asserts the override returns B's own row, and updates by A's role id (count 0, A's row unchanged).

Other notes: `stateUpdateData` (a shared helper in inbox-fixtures.ts used by lifecycle-fixtures.ts) carries the pause invariant for both fixtures. The SUMMARY records race PIDs as a run-time mechanism, not values (the output spec asked for PIDs; they differ every run).
