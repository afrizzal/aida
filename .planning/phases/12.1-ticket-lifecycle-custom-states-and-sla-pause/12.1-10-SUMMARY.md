# Phase 12.1 Plan 10: Inbox filter, URL and loader on state ids Summary

The inbox filter grammar, URL, list query and panel loader now use state ids instead of enum statuses. A state= parameter that is present but empty or malformed fails closed to a sentinel, so it can never widen the inbox. Old status= bookmarks get a server replace-redirect to the canonical URL. The Status filter is grouped by state group, and missing ids show up both in the menu and as a removable notice.

## Frozen URL contract (D-09, D-19, UI-SPEC Assumption 6)

- **Param name:** `state`, holding state ids joined by `,`. The canonical form puts the ids in code-unit order (default `sort`), de-duplicated. `filtersToSearchParams` writes the params in this order: `view` (only when not all), `state`, `tag`, `cf`, `q`, `snoozed=1`. It never writes `limit`. An empty list writes no `state` param.
- **Presence rule:** only an ABSENT `state` param means there is no state filter.
- **Floor:** for a present value, the parser splits on `,`, trims each token and drops empty tokens. A token that does not match `/^[A-Za-z0-9_-]{1,64}$/` becomes the sentinel `LEGACY_UNMAPPED_STATE_ID` (`unmapped-legacy-status`); it is never dropped. The ids are then de-duplicated and sorted. If nothing is left, the result is `[LEGACY_UNMAPPED_STATE_ID]`. This covers `state=`, `state=,,,` and `state=%20%20`.
- **Schema-failure fallback:** the filters fall back to `{ view: "all", stateIds: [sentinel] }` when the param was present, and to `[]` only when it was absent.
- **Query:** a non-empty `stateIds` gives `where.stateId = { in: ids }`. A list where every id is missing matches nothing.
- **Missing ids:** these are ids that are not an active state of the organization (deleted, unknown, belonging to another org, or the sentinel). `missingStateIds` reports them, and it always counts the sentinel as missing.
- **Legacy redirect:** `TicketListPanel` (only when `membershipActive`) calls `legacyRedirectSearch(searchParams, legacyStateIds)`. When the URL has a `status` param (a present but empty one counts too), the panel calls `redirect(basePath + "?" + search, RedirectType.replace)`. `status` is removed. `state` becomes the sorted union of the URL's own state ids and the mapped ids, and it takes the slot of whichever of the two params came first. All other params are kept. `mapLegacyStatusParam` matches the five keys case-insensitively. An unknown key, a key whose state is soft-deleted, or a present value that maps to nothing becomes the sentinel. The redirect target is the panel's own basePath, so no host or path comes from the input (T-12.1-40).
- **Stored views:** `{ version: 2, view, stateIds (sorted), tagId?, cf?, q?, snoozed? }`. `parseStoredFilters` returns null for any other version.

## Deviations from Plan

**1. [Rule 1 - Bug] MissingStatusNotice takes `missingIds` instead of `missingCount`**
- **Found during:** Task 3
- **Issue:** a notice that only gets a count cannot remove the missing ids, so the plan's `MissingStatusNotice({ missingCount })` signature could not do its job.
- **Fix:** the prop is `missingIds: string[]`, and the label count is `missingIds.length`. Removal rebuilds `state` from the grammar's ids minus the missing ones. Malformed tokens have already become the sentinel at that point, so they are removed as well. If nothing is left, the `state` param is deleted.
- **Files modified:** src/app/(app)/tickets/missing-status-notice.tsx, src/app/(app)/tickets/ticket-list-panel.tsx
- **Commit:** ec943aa

**2. [Note] LEGACY_STATUS_KEYS type name.** `ticket-states.ts` (12.1-01) already exports a type called `LegacyStatusKey`. To avoid two exports with the same name, list-filters.ts names its key type `LegacyStatusParamKey`. The constant `LEGACY_STATUS_KEYS` is defined locally because the module has to stay client-safe (`grep -c '@/'` prints 0).
