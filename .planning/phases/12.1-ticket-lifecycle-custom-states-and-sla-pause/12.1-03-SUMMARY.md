## Recovery sequence that worked (operator notes)

1. Fix the saved view the error names (the test set it to version 1 with statuses `['OPEN']`).
2. A plain `pnpm prisma migrate deploy` exits 1: `Error: P3009 migrate found failed migrations in the target database, new migrations will not be applied ... The 20261110100000_ticket_states migration started at ... failed`.
3. `pnpm prisma migrate resolve --rolled-back 20261110100000_ticket_states` exits 0 (`Migration 20261110100000_ticket_states marked as rolled back.`). This is correct only because the failed run changed nothing (proven above); never use `--applied`.
4. `pnpm prisma migrate deploy` exits 0.

End state: two `_prisma_migrations` rows for the migration, the failed one with `rolled_back_at` set and `finished_at` null, and one finished row (`applied_steps_count` 1, `rolled_back_at` null); Ticket.status gone; every ticket in the state of its old value; the fixed view is `{ version: 2, view: 'all', stateIds: [A's Open id] }`.

Success: a second populated database (no malformed view) deployed with exit 0, one finished row, fixture coverage empty before, the column-by-column comparison equal, mapping and pause start as on the harness path.
