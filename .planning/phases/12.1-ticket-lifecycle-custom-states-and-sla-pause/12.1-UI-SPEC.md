# Phase 12.1 — UI Design Contract

> Visual and interaction contract for the UI parts of Phase 12.1 (AIDA-56 custom states, AIDA-97 state management, AIDA-57 SLA pause). Generated by gsd-ui-researcher under the run charter (unattended, no user questions); every choice not fixed upstream is marked **[RL]** and listed under "Assumptions". To be verified by gsd-ui-checker.
>
> **Binding parent:** `.planning/DESIGN-SYSTEM.md`. Everything here refines it and never overrides it. Conventions carried over from the approved `12-UI-SPEC.md` (which carried them from Phase 11): spacing scale 4/8/16/24/32, 16px callout padding, `text-[13px]` overrides on shadcn internals, 15px dialog titles, inline `role="alert"` errors in dialogs, toasts for success, "refusal returned → Nothing was changed; call rejected → result not known" (P11 D2), disabled-with-reason menu items (P12 Surface 1), `LocalDateTime` for visible times (P12 4a).
>
> **Scope (closed list):** (1) a new settings page for ticket states with create, rename, recolour, reorder, set default and delete; (2) the state chip that replaces `StatusChip` everywhere; (3) the state picker in the ticket top bar and in the bulk action bar; (4) the inbox Status filter, saved-view summary and strip, and the missing-reference treatment for a deleted state; (5) the SLA "paused" indicator; (6) the public status page group label; (7) status rows in the activity feed, including deleted states. No other surface changes. Phases 8, 9 and 10 are parked: no notification, no `BrandMark`, no no-access page, no CSP exists, and nothing here assumes them. AI stays out: nothing here calls `lib/llm/`.

Source legend: **[CTX D-nn]** = locked in `12.1-CONTEXT.md`; **[REQ]** = `REQUIREMENTS.md` AIDA-56, AIDA-97, AIDA-57; **[DS §n]** = `DESIGN-SYSTEM.md`; **[code]** = existing code at `e37b2f4`; **[P11]** / **[P12]** = convention reused from `11-UI-SPEC.md` / `12-UI-SPEC.md`; **[RL]** = Claude's discretion (run-loop), decided conservatively because no upstream artifact answers it.

**Terminology [RL, Assumption 1]:** the data model says "state" (`TicketState`); every user-facing string says **"status"**, as the product already does ("Status" filter, "Change status" menu and palette command, "changed the status from … to …" feed rows, bulk "Status" picker). A state's group is called its **group** in copy ("the Pending group"). Below, "state" names the code concept and "status" the copy.

## Spacing Scale

Declared values (multiples of 4), mapped to Tailwind classes:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px (`gap-1`, `space-y-1`) | Row control cluster gap; chip icon-to-text gap; consequence list stack; group description under its heading |
| sm | 8px (`gap-2`, `px-2`, `py-2`, `space-y-2`) | Status row vertical padding and item gap; colour option gap; dot-to-name gap in pickers; preview line gap |
| md | 16px (`p-4`, `px-4`, `py-4`, `gap-4`, `space-y-4`) | Group card header and row horizontal padding; callout padding [P11]; dialog body stack [DS §6]; gap between the group cards |
| lg | 24px (`space-y-6`) | Settings page stack (existing `SettingsLayout` and page `space-y-6`) |
| xl | 32px (`py-8`) | Vertical padding of the "no statuses in this group" line |
| 2xl | 48px | Not used |
| 3xl | 64px | Not used |

Exceptions (each inherited, none invented here):
- **Chip vertical padding `py-0.5` (2px), declared and kept:** `StateChip`, the paused branch of `SlaDueChip` and `PublicGroupChip` use `h-5 px-2 py-0.5`, copied from the existing chips (`status-chip.tsx:19`, `sla-due-chip.tsx:34`, `:49`, `:63` [code]). Reason: the chip height is fixed by `h-5` (20px), so the 2px is not layout spacing; keeping the same class string keeps the new chips identical in height and baseline to the chips they sit beside. No other new element uses a 2px value.
- `SettingsNav` keeps its existing `gap-1.5`; it gains `flex-wrap gap-y-2` so seven items wrap at narrow widths (Surface 1a).
- The inbox filter row keeps its existing `gap-1.5 gap-y-2`; the top bar keeps its existing `gap-2` and `gap-3`; the bulk bar keeps its existing layout.
- shadcn internals (`DropdownMenuItem` `px-1.5 py-1`, `CommandItem` `px-2 py-1.5`, `DialogContent` padding, `SelectItem`, Button size paddings) stay as shipped; only font sizes are overridden on instances.

Sizes, not spacing: chips `h-5` (matching the old `StatusChip`); chip name `max-w-[160px] truncate`; dot `size-2 rounded-full`; row icon buttons `size-8`; status row `min-h-12`; add/edit dialog `sm:max-w-[480px]`; delete dialog `sm:max-w-[520px]`; picker menus `w-[240px] max-h-[320px] overflow-y-auto`.

**Every other spacing value used by a new element is on the declared scale (4, 8, 16, 24, 32). No 6px (`gap-1.5`) or 10px (`gap-2.5`) in new elements.**

## Surface 1 — Ticket statuses settings page (AIDA-97, D-03, D-05, D-06, D-12, D-14, D-15)

### 1a. Route, navigation and access

- Route `/settings/statuses` [RL]. `SettingsNav` gains the item `{ href: "/settings/statuses", label: "Statuses" }` after "SLA Policies" [RL], with the existing active and inactive styles. The nav container becomes `flex flex-wrap items-center gap-1.5 gap-y-2`.
- The page is server-rendered. It checks active membership first (`findActiveMembership`) [CTX D-01]; a session whose member row is gone gets the Copywriting "Membership ended" line in place of the page body.
- **Admins (exact `owner` or `admin`, `isAdminRole`)** get every control below. **Other members** get the same list read-only: no "Add status" button, no row controls, and one 13px muted line under the page description: Copywriting "Members note" [RL, the existing auto-close and branding pattern; code]. Every action refuses a non-admin on the server anyway [CTX D-01].

### 1c. Status row

`<li className="flex min-h-12 flex-wrap items-center gap-2 px-4 py-2">`:

2. When the state is the default (`newStateId`): `Badge variant="secondary" className="h-5 px-2 text-[12px]"` with Copywriting "Default badge".
3. Ticket count, `text-[12px] text-muted-foreground tabular-nums`: Copywriting "Ticket count".

   - Move down: same with `ArrowDown`, Copywriting "Move down (aria-label)".

     - "Use for new tickets" (`Star`) → set default (1f). ## Assumptions (Claude's discretion, recorded for the planner) [RL]

1. **Copy says "status"; code says "state".** No existing string that says "status" is renamed. The settings page is "Ticket statuses" at `/settings/statuses`, nav label "Statuses", after "SLA Policies".
2. **Palette:** eleven keys (ten tinted tokens plus "Indigo, filled" on `--primary`), names and order as in the Color section; starting token values given there, adjusted only in lightness if a contrast test fails. Migration colours New → `indigo-filled`, Open → `indigo`, Pending → `amber`, Resolved → `green`, Closed → `gray`.
3. **Names:** trimmed, 1 to 40 characters, unique per organization case-insensitively (D-03). **No cap on the number of statuses per workspace** (orchestrator decision, revision 1: a cap is not in the requirements); there is no "limit reached" refusal.
4. **Non-admin members** see the page read-only with the members note, like the branding and auto-close settings; every action is refused on the server.
5. **Creation is per group** ("Add status" in each group card), so the group is chosen by where the admin clicks and never offered as an editable field; the dialog says the group is fixed.
6. **URL:** the filter writes `state=<ids>`; legacy `status=<ENUM>` is read by the compatibility mapper. The planner freezes the exact contract (D-09, D-19) and may keep one param name if it records why.
7. **Missing ids** match no ticket, appear in the filter menu as checked "A deleted status" items, and trigger the URL notice when no saved-view strip is shown.
8. **Paused chip:** neutral in all cases; "SLA paused, overdue" when the breach flag was already set; no at-risk variant while paused (the clock is stopped).
9. **Top-bar refusals** keep the header's existing `toast.error` channel (every header field uses it today); the outcome-unknown toast stays until dismissed.
10. **Reorder** is within a group, one step per press, not optimistic, announced through a polite live region, with `aria-disabled` end buttons so focus never drops.
11. **Delete dialog** does not preselect a replacement; the count is the snapshot at open time, and the server moves every ticket present at execution time (D-15); the role list names only the roles the state holds.
12. **Role wording** ("tickets are resolved here" for `resolveStateId`) is generic because no reader of that role is listed yet; the planner adjusts the row text once the D-11 reader list names its users, and records the change.
13. **Public chip colours** use the state palette tokens for the four groups, so the public page passes the same contrast test.
