# Phase 12.1 Plan 11: Picker, palette, merge dialog and contact page on states Summary

The ticket picker, the command palette search, the merge confirmation pair and the contact page's ticket list now show each ticket's state name and colour token (StateChip) instead of the enum status. The full-text search is joined to TicketState inside the ticket's own organization.

## Response shapes

- **GET /api/tickets/picker** (200): `{ results: [{ id, number, subject, stateName, colorToken, alreadyLinked, linkLabel, sameContact, mergedSource }] }`, at most 10 rows. Errors are unchanged: 401 `unauthorized`, 403 `no_workspace`, 404 `not_found`, and 403 `membership_ended` (checked before any search).
- **GET /api/palette/tickets** (200): `{ results: [{ id, number, subject, stateName, colorToken }] }`, at most 10 rows. The membership-first refusal is unchanged.
- `stateName` and `colorToken` are the name and colour key of the ticket's state in the actor's organization. A number lookup reads them through the composite `state` relation. A word search reads them from `searchTickets`, which uses `JOIN "TicketState" s ON s.id = t."stateId" AND s."organizationId" = t."organizationId"` and keeps the `t."organizationId"` filter. Nothing else about the state is returned.
