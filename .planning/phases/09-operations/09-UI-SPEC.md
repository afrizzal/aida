## Surface 1 — Settings → Branding (`/settings/branding`)

Page structure (top to bottom inside the settings layout, `space-y-6`):

1. Existing header block, unchanged: visible `<h1>` "Branding" + 13px subtitle. Subtitle copy changes to: "Your workspace name and logo. Shown in the sidebar, on your public request and status pages, and (name only) as the from-name on outbound email."
2. **Name card** (existing `BrandingForm`, unchanged behaviour). Its preview row now renders `<BrandMark variant="sidebar" name={previewName} logoUrl={currentLogoUrl} />` inside the existing `rounded-md border border-sidebar-border bg-sidebar px-4 py-3` box, so the preview shows exactly what the sidebar will show.
3. **Logo card** (new), `Card className="border-border/70 p-4 shadow-sm"`, `space-y-4`:
   - `<h2 className="text-[15px] font-semibold tracking-tight">Logo</h2>`
   - Help text, 12px `text-muted-foreground`, id-linked to the file input via `aria-describedby`: "PNG, JPEG or WebP. Up to 1 MiB and 1024 × 1024 pixels. SVG is not accepted. Use a logo that reads on both light and dark backgrounds."
   - **No logo:** 13px muted line "No logo uploaded. The sidebar and public pages show the default icon." then the button row with **Upload logo** (default `Button`, `Upload` icon `size-4`).
   - **Logo set:** preview plate `flex h-16 w-40 items-center justify-center rounded-md border border-border/70 bg-muted/40 p-2` containing `<img className="max-h-full max-w-full object-contain" alt="Current workspace logo">`; then the button row (`flex gap-2`): **Replace logo** (`variant="outline"`, `Upload` icon) and **Remove logo** (`variant="ghost"`, `className="text-destructive"`, `Trash2` icon).
   - **Non-admin (role not owner/admin):** preview (if any) is shown, no buttons, 13px muted line "Only workspace admins can change the logo." [code: matches the existing name-field notice].
   - Inline error slot below the button row (see Interaction).

Interaction contract:
- The buttons trigger one visually hidden `<input type="file" accept="image/png,image/jpeg,image/webp" class="sr-only" aria-label="Logo file">`. Selecting a file **uploads immediately** (no separate Save) [RL: a file pick is the commit gesture; the name field keeps its own Save].
- Client pre-check before sending: extension/MIME in the accepted list, size ≤ 1,048,576 bytes. On failure show the inline error and send nothing. The server re-checks everything by byte sniffing (`file-type`), header-read dimensions and role [CTX D-08]; the server result is authoritative and its error code maps to the same copy.
- While uploading: the pressed button shows `Loader2 className="mr-2 size-4 animate-spin"` and the label "Uploading…"; both buttons are disabled; the file input is reset after every attempt so the same file can be re-picked.
- Success: `toast.success("Logo uploaded.")` (or "Logo replaced."), inline error cleared, preview plate, Name-card preview and sidebar update without a full reload (`revalidatePath("/", "layout")`, as `saveBranding` already does).
- Remove: opens the confirmation Dialog (Copywriting). Confirm button shows the spinner and "Removing…" while pending; success closes the dialog and fires `toast.success("Logo removed.")`; failure keeps the dialog open and shows the error inside `DialogDescription`'s area as a 13px `text-destructive` line with `role="alert"`.
- Inline error element: `role="alert"`, pattern `flex items-center gap-2 rounded-lg border border-destructive/20 bg-destructive/10 p-3 text-[13px] text-destructive` with `CircleAlert className="size-4 shrink-0"` [code: `email-health-line.tsx`]. Cleared on the next file pick.
- Keyboard: buttons are native `<button>`; Dialog traps focus and returns it to "Remove logo" on close (radix default).

Dimension cap [CTX D-08 discretion → RL]: **1024 px on each side** maximum; no minimum. Rejected, never resized server-side.

## Surface 2 — Brand mark (sidebar, preview, public shell)

`BrandMark` contract:

| State | Render |
|-------|--------|
| No logo (`logoUrl` null) | Existing markup verbatim: `div.flex.size-7.shrink-0.items-center.justify-center.rounded-md.bg-sidebar-primary.shadow-sm` > `Sparkles.size-4.text-sidebar-primary-foreground`, then the name span |
| Logo set | Bounded box `flex h-7 shrink-0 items-center` with `max-w-[72px]` (sidebar) or `max-w-[120px]` (public), containing `<img src={logoUrl} alt="" height={28} className="h-7 w-auto max-w-full object-contain">`; then the name span |
| Logo fails to load (`onError`) | Switches to the Sparkles box for the rest of the render lifetime; no error text |

- Row: `flex items-center gap-2.5` (sidebar keeps its `h-14 px-4` header) [DS §4.1].
- **The name is always visible** next to the logo or icon: `min-w-0 truncate text-[15px] font-semibold tracking-tight text-sidebar-foreground` (sidebar) / `text-[15px] font-semibold tracking-tight` (public). With the 72px logo cap, at least 126px of the 240px sidebar remains for the name before truncation.
- `alt=""` because the adjacent visible name already names the brand; screen readers announce the name once [RL].
- No rounded corners, background plate or border on the logo itself; `object-contain` never crops [CTX D-11].
- `logoUrl` is the versioned public URL from D-09 (version in the URL so the long cache never serves a stale logo after replace). Plain `<img>`, not `next/image`, so no image-optimizer route is added [RL].

## Surface 4 — Backup status (`/settings/backups`)

Page (`space-y-6`):
1. Header: visible `<h1 className="text-[18px] font-semibold">Backups</h1>` + 13px muted subtitle: "AIDA backs up its database and uploaded files on this server on a schedule. This page shows the most recent run. The schedule, retention and the off switch are server settings described in docs/OPERATIONS.md."
2. Body by state:

| State | Render |
|-------|--------|
| Non-admin | 13px muted line "Only workspace admins can see backup status." Nothing else is read or rendered. |
| No record yet | `EmptyState` (default `h2`) icon `DatabaseBackup`, heading/body per Copywriting [DS §4.3] |
| Last run succeeded | Card (below) with result badge `Succeeded` (`Badge` with `bg-success/10 text-success border-transparent`, `CircleCheck` `size-4`) |
| Last run failed | Card with result badge `Failed` (`bg-destructive/10 text-destructive border-transparent`, `CircleAlert`), plus the failure callout under the list |

Card: `Card className="border-border/70 p-4 shadow-sm"` > `<h2 className="text-[15px] font-semibold tracking-tight">Last backup</h2>` > `<dl className="grid grid-cols-[auto_1fr] gap-x-4 gap-y-2 text-[13px]">` [code: contact detail `dl`]:

| `dt` (muted) | `dd` |
|--------------|------|
| Result | badge |
| Finished | `<time dateTime={iso} title={absolute local time}>{formatRelativeTime(...)}</time>` followed by the absolute time in 12px muted, e.g. "2 hours ago · 8 Nov 2026, 02:00" |
| Backup set | set id in `font-mono`; on failure with no published set: "None — this run did not publish a set" |
| Failure reason | only when failed: the category sentence (Copywriting) |

Failure callout (failed only), `role="status"` (not `alert`; it is not a live event): destructive callout pattern with copy "Check the backup service logs with `docker compose logs backup`. The next scheduled run tries again on its own." Failure categories are the planner's enum [CTX D-04]; each maps to one fixed sentence, and any unknown category maps to the generic sentence. Raw error text is never shown.
