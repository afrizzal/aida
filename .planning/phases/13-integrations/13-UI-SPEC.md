## Typography

Sizes used by new elements (4 sizes, 2 weights):

| Role | Size | Weight | Line height | Where |
|------|------|--------|-------------|-------|
| Caption | 12px (`text-[12px]`) | 400 | 1.5 | Row meta lines, field help, token prefix and URLs (`font-mono`), delivery times, chip text |

| Secondary (30%) | `--card`, `--popover`, `--muted` | Cards, dialogs, menus, preview block `bg-muted/40` |
| Accent (10%) | `--primary` (bg) / `--primary-emphasis` (text) | Reserved list below only |

Neutral badges ("Off", "Expired", "Revoked", "Pending", "Read only", "Read and write") use `variant="secondary"` or `variant="outline"`, never a state or accent colour. "Enabled" uses `variant="outline"` with a `size-2 rounded-full bg-success` dot before the text; colour is never the only signal (the word is always shown).

Accent reserved for (closed list):
1. Primary CTAs: "Create token", "Add webhook", "Save webhook", "Set up GitHub", "Set up Plane", "Save connection", "Escalate" (dialog submit "Create issue"), "Done" in the shown-once view.
2. Checked `Switch` track and checked `Checkbox` (shadcn defaults).
3. Active settings tab `bg-primary/10 text-primary-emphasis` (existing; applies to the new tabs) [code: `settings-nav.tsx`].
4. Focus rings (`--ring`) and the EmptyState icon box (`bg-primary/10 border-primary/15`) [DS §4.3].
5. The external-issue link text inside a `LINKED` chip: `text-primary-emphasis` [DS §1 rule of thumb].

Never `text-primary` as text on a tinted or dark surface; use `text-primary-emphasis` [DS §1].

**Revoke dialog**: title, description, "Keep token" (outline) and **Revoke token** (destructive), pending "Revoking…"; success closes, toast, row moves to the inactive group with "Revoked"; failure keeps the dialog open with the error `role="alert"` above the footer. ### Shown-once secret view (shared, `ShownOnceSecret`)

Used for: new API token, new webhook signing secret, rotated signing secret, new tracker inbound secret. It replaces the dialog's form view in place (same `DialogContent`).
- Title per Copywriting ("Copy your new token" / "Copy the signing secret" / "Copy the inbound secret").
- Warning callout with the matching "Shown-once notice" row.
- Read-only `Input` (`font-mono text-[12px]`, `readOnly`, `aria-label` per Copywriting, `aria-describedby` → the notice), selected on focus, scrolls inside itself; **Copy** button (outline, `Copy` icon) beside it in a `flex gap-2` row that wraps under 360px; after copying the label becomes "Copied" with `Check` for 2 seconds, announced by an `aria-live="polite"` `sr-only` span ("Copied to the clipboard."). Clipboard failure: the span says "Could not copy. Select the text and copy it yourself." and the field stays selected.
- Footer: **Done** (default) only. Clicking outside does not close this view (`onInteractOutside` prevented); Escape and Done close it. Once closed the value is gone from client state and is never fetched again; no server action returns it a second time (CTX D-01, D-07).
- On switch to this view, focus moves to the secret `Input`, and a polite live region announces the dialog title.
- The value never goes into a toast, the URL, `localStorage`, logs or an error message.

- Shown to every current member with access to the ticket (CTX D-13); hidden on a merged-source ticket [RL].
- When every enabled connection already has a link for this ticket, the button is disabled with Tooltip "This ticket already has an issue in every connected tracker." (`aria-describedby` to the tooltip text) [RL].

**Dialog** (`DialogContent className="sm:max-w-[560px]"`), `space-y-4`:
- Title "Escalate ticket #{number}"; 13px muted description.
- **Send to** `Select` (`aria-label` from the visible Label): one option per enabled connection, text "{Provider} · {display name}"; a connection already linked to this ticket is listed disabled with suffix " (already linked)". With exactly one option, the Select is shown preselected.

## Accessibility contract

- **Labels:** every input has a visible `<Label htmlFor>`; help and errors are joined into `aria-describedby` (help id first, error id when present); invalid fields set `aria-invalid`. Icon-only buttons have `aria-label` and a Tooltip with the same words. Switches carry the "Enable …" labels and `aria-describedby` → their status badge.
- **Headings:** one `<h1>` per page inside `<main>` (the top bar title stays a `<p>`, DS §4.2); card titles `<h2>`; dialog titles via `DialogTitle`.
- **Focus order:** Developers page → subtitle content → API tokens card (Create token, then rows in order: Revoke) → Webhooks card (Add webhook, then per row: Switch, More actions). Integrations page → GitHub card → Plane card (per card: Set up, or Switch, Test connection, Edit, Copy URL, Rotate inbound secret). Ticket header: existing controls in order, Escalate before the snooze control and the actions menu; chips in the second row after custom fields. Dialogs trap focus (radix), open on the first field, and return focus to the trigger; after a row disappears (revoke moves, delete removes), focus goes to the card `<h2 tabIndex={-1}>`.
- **Live regions:** shown-once view announces its title (polite) and moves focus to the secret field; copy result (polite); connection test result (polite); inline errors `role="alert"`; a pending chip uses `role="status"`. Toasts are sonner's own live region and carry no secret.
- **Keyboard:** all actions reachable by Tab, Enter and Space; Escape closes dialogs and menus (outside click does not close the shown-once view); the Checkbox gate on "Create anyway" is keyboard-operable.
- **Motion:** spinners use `motion-reduce:animate-none`.
- **Contrast:** only tokens already proved at 4.5:1 (DS §2 contrast notes); warning text on its `/10` tint is an existing pattern; dark mode is a human item.

## 360px behaviour

- The settings nav already wraps (`flex-wrap`); the two new pills wrap onto the next line.
- Every row is `flex flex-wrap`; badges, switch and actions move under the identity block; names, URLs and prefixes truncate (full value in `title`); nothing scrolls horizontally.
- Card headers wrap: the CTA moves under the heading.
- Dialogs use the shadcn default `max-w-[calc(100%-2rem)]`; the secret Input scrolls inside itself and the Copy button wraps under it; footers stack (`flex-col-reverse sm:flex-row`, the shadcn default).
- Integrations detail `<dl>` keeps two columns; long values `break-all`.
- Ticket header: Escalate collapses to an icon button below 640px; chips wrap in the second row.
- Deliveries rows wrap the detail line under the badge.
