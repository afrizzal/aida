**Existing headless bootstrap** (`src/lib/bootstrap.ts`) — the precedent D-02 builds on:
```ts
export async function bootstrapFromEnv(): Promise<void> {
  const email = process.env.ADMIN_EMAIL; const password = process.env.ADMIN_PASSWORD;
  const name = process.env.ADMIN_NAME ?? "Admin";
  if (!email || !password) return;                 // env absent -> no-op
  if (await prisma.user.count() > 0) return;       // idempotent
  const signUpResponse = await auth.api.signUpEmail({ body: { name, email, password } });
  const orgResponse = await auth.api.createOrganization({ body: { name: "AIDA", slug: "aida", userId } });
  await prisma.systemSetting.upsert({ where: { key: "setupComplete" }, update: { value: "true" }, create: { key: "setupComplete", value: "true" } });
}
```
It is called from `src/instrumentation.ts`'s `register()` under `process.env.NEXT_RUNTIME === "nodejs"`.

**Adding a SECOND user to an org** (proven in `tests/e2e/global-setup.ts`): `auth.api.signUpEmail(...)` then a direct
`prisma.member.create({ data: { id: randomUUID(), organizationId, userId, role: "member", createdAt: new Date() } })`.
Better Auth's `member` model has no `organizationId`-scoped helper here; the direct create is the established pattern.

**From Plan 07-02** (read its SUMMARY for the actual signatures):
```ts
seedDemoData({ orgId, adminUserId, agentUserId, now? }): Promise<SeedDemoSummary>
```
and `prisma/seed.ts` already contains identity-creation logic that THIS plan extracts into a shared module so the two paths cannot drift.

**Compose facts:** the `app` service's `environment:` block already forwards `ADMIN_EMAIL`/`ADMIN_PASSWORD`/`ADMIN_NAME` with `${VAR:-}` defaults. Its healthcheck is `interval: 10s, timeout: 5s, retries: 5` with **no `start_period`** — a boot-time seed that takes longer than ~50s would mark the container unhealthy. Only the `app` service needs the DEMO_* variables (the worker does not seed).

**Ops docs marker:** `docs/OPERATIONS.md` (Plan 07-04) contains `<!-- 07-07 adds DEMO_MODE here -->` at the end of its environment-variable table. Replace that marker with the new rows.

**Security posture that the Plan 07-09 security pass will audit:** demo mode ships known credentials. It must therefore be (a) inert unless `DEMO_MODE` is exactly `"true"`, (b) never the default in `.env.example`, and (c) loud in the logs. It must NOT write any real secret and must NOT enable AI.
