**Deployment target:** the git remote is `https://github.com/afrizzal/aida.git`, so GitHub Pages serves a PROJECT page at `https://afrizzal.github.io/aida`. Astro therefore needs BOTH:
```js
site: 'https://afrizzal.github.io',
base: '/aida',
```
Omitting `base` breaks every asset and link on the deployed site.

**The canonical GitHub Pages workflow for Astro** (from the Astro docs) is:
```yaml
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: withastro/action@v6
        with:
          path: ./website
          package-manager: pnpm@latest
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v5
```
`withastro/action` installs dependencies, builds, and uploads the Pages artifact itself — do NOT add separate setup-node/install/build steps.

**Starlight scaffolding:** `pnpm create astro@latest website -- --template starlight` is the supported entry point. Run it NON-INTERACTIVELY. Whatever content-collection layout the generated scaffold produces (a `content.config.ts` at `website/src/`, or `src/content/config.ts` — this differs between Starlight versions) is authoritative: keep it, do not rewrite it to match an older tutorial. Only edit `astro.config.mjs` (site/base/title/sidebar/social) and the content files.

**Isolation hazards — the root config files WILL pick up `website/` unless changed:**
- `tsconfig.json` has `"include": ["next-env.d.ts", "**/*.ts", "**/*.tsx", ...]` and `"exclude": ["node_modules", "src/generated", "prisma.config.ts"]`. Without adding `website` to `exclude`, `pnpm typecheck` will try to compile the Astro project.
- `biome.json` `files.includes` is `["**/*.{ts,tsx,js,jsx,json}", "!**/node_modules", ...]` — `website` must be added as a `!` negation or `pnpm lint` will format the Astro scaffold.
- `.dockerignore` currently has no `website` entry — without one, the docs site is copied into the product build context (it is already excluded from the image content, but it bloats context transfer and invalidates layer caches).
- `.gitignore` needs `website/node_modules/`, `website/dist/`, `website/.astro/`.

**Content sources for the quick-start page** (must match reality, not the current README, which contains a known error): `docker compose up` serves the app through **Caddy on `http://localhost` (port 80)** — NOT `http://localhost:3000`. Port 3000 is internal to the compose network. The compose stack is `db` + one-shot `migrate` + `app` + `worker` + `caddy`. `.env.example` is the canonical variable list; `BETTER_AUTH_SECRET`, `RATE_LIMIT_PEPPER` and `APP_ENCRYPTION_KEY` are each generated with `openssl rand -base64 32`.

**Honest-claims rule (CLAUDE.md)** applies to every word of docs copy: no invented metrics, never say a model is "trained" or "fine-tuned" (models are consumed via API / orchestrated).

        paths:
          - 'website/**'

          name: github-pages
          url: ${{ steps.deployment.outputs.page_url }}

          - name: Deploy to GitHub Pages
