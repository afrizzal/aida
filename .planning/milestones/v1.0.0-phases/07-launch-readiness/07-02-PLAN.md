**Two behavioural facts that shape the design:**
1. `createTicket` enqueues an `ai-triage` pg-boss job ONLY when `Setting.aiEnabled === "true"`. The seed MUST NOT write `aiEnabled=true`, so no queue traffic is generated for tickets.
2. `createKbArticle` ALWAYS calls `getBoss()` and `boss.send("kb-embed-article", ...)`. That opens a pg-boss connection and installs the pg-boss schema on a fresh DB (a few seconds, harmless). The CLI entrypoint must therefore end with `await prisma.$disconnect(); process.exit(0);` or the process will hang on the open pg-boss pool.

**`createTicket` always stamps `createdAt = now()`.** Historical timestamps are produced by a follow-up `prisma.ticket.update` (allowed by D-01). `Ticket.updatedAt` is `@updatedAt` but Prisma honours an explicitly-passed value. The inbox sorts by `createdAt: "desc"` (`src/lib/tickets/list-query.ts:115`), so backdating `createdAt` is what drives realistic list ordering.

**Direct-write models (no helper exists):** `Tag`, `TicketTag`, `CustomFieldDefinition`, `CustomFieldValue`, `CsatResponse`, `InsightRun`, `member`. Write these with bare `prisma.<model>.create({ data: { organizationId, ... } })` — an explicit `organizationId` on every row (this is a script, not a request; there is no session to scope from).

**`AuditEvent` is append-only** (Postgres trigger `aida_audit_event_no_update_delete` raises on UPDATE *and* DELETE). Consequence: a "reset and re-seed" path is impossible for audit rows. The guard must therefore REFUSE on a non-empty workspace rather than offer a destructive reset.

**InsightRun JSON shapes** are defined in `src/lib/insight/types.ts` — `InsightRunParams`, `StoredCluster`, `StoredKbGap`, `VolumeDrivers`, `SlaCsatSummary`, `StoredNarrative`. Import and type against them; never redefine the shapes inline. A worked reference instance of all five columns exists at `tests/e2e/phase6-insight.spec.ts` `seedCompletedRun()` (lines ~61-140) — copy its structure, but with REAL seeded ticket ids/numbers/subjects in every `citations[]` entry.

**Honest-claims constraint (CLAUDE.md).** These artifacts are pre-computed demo data, not the output of a real model call. Every seeded `AuditEvent` and `InsightRun` MUST use `provider: "demo"` and `model: "demo-seed"` (and `embeddingModel: "demo-seed"` on InsightRun) so the UI never implies a real vendor call happened.

**tsx resolves the `@/` alias** from the root `tsconfig.json` (verified). `prisma/seed.ts` may freely import `@/lib/...` modules.
